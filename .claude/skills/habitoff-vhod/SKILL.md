# Вход в контекст Habitoff

Этот скилл не содержит правил проекта — он говорит, где они лежат и в каком порядке
берутся. Правила живут в `AGENTS.md`, и дублировать их здесь нельзя: два описания одного
правила расходятся за неделю.

## Порядок, обязательный для любой роли

1. `docs/NAVIGATOR.md` — карта: что читать по теме, где брать состояние, какие расхождения
   уже известны. Раздел «Известные расхождения» читается всегда: он избавляет от спора с
   документом, о котором уже известно, что он неверен.
2. `bash scripts/state.sh` — фактическое состояние. **Первая строка — отставание локального
   `main` от `origin/main`.** Есть отставание — работа от этой копии недостоверна, сначала
   `git fetch` и обновление.
3. `AGENTS.md` — инварианты и таблица «правило → проверка».
4. Два-три документа по теме задачи — те, что названы в навигаторе.
5. Действующие ADR по теме.
6. Файл постановки `docs/tasks/T-….md` и разбор, из которого она выросла.
7. Только затем — код.

## Что считается фактом

Факт о репозитории, доске, сервере или проде — это вывод команды в этом заходе. Не вывод —
это предположение, и оно называется предположением вслух.

| Вопрос | Команда |
|---|---|
| Что с репозиторием и доской | `bash scripts/state.sh` |
| Есть ли работа только на этой машине | `node scripts/check-local-drift.mjs` |
| Отстал ли прод от `main` | `node scripts/check-deploy-drift.mjs` |
| Что сейчас на проде | `https://habitoff.ru/version.json` |
| Что уже есть по направлению | `docs/board/cards.json`, `node scripts/tasks.mjs` |
| Свободный номер постановки | `bash scripts/next-id.sh <R\|T\|session>` |

## Три вещи, которые ломают работу чаще всего

- **работа от отставшей копии.** Локальный `main` регулярно отстаёт на сотню коммитов;
  прочитанный из него документ — прошлогодняя редакция;
- **«впереди на N коммитов» ≠ «не выложено».** Ветка может быть влита в `main` под другим
  SHA. Невыложенное считается содержимым (`git diff origin/main...ветка`), а не числом;
- **вторая сущность вместо расширения первой.** Прежде чем заводить новый объект, назови
  тот, что уже решает эту задачу. Не получается объяснить, почему его мало, — расширяй его.

## Куда писать результат

Постановка — `docs/tasks/`. Решение — ADR в `docs/decisions/`. Состояние — командой, а не
документом. Найденное попутно — трейлером `Board: new` в том же коммите. Журнал того, что
ломалось, — `docs/INCIDENTS.md`.
