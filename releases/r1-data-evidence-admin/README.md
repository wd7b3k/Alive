# R1 — данные, доказательная база и контроль продукта

## Цель

Создать фундамент, поверх которого следующие пользовательские релизы смогут последовательно реализовывать финальную продуктовую стратегию ALIVE.

R1 отвечает на три задачи:

1. сделать Триггеры, Замены и «Зачем» полноценными персонализируемыми сущностями;
2. создать управляемую и актуализируемую доказательную базу Фактов/Мифов;
3. сразу дать владельцу продукта админский контур для контроля востребованности, воронки, ценности и технического здоровья.

## Что меняется

### Данные и персонализация

- категории Триггеров;
- собственные Триггеры пользователя;
- категории Замен;
- собственные Замены пользователя;
- пользовательские настройки общей Замены;
- контекстные правила вмешательства;
- новая сущность «Зачем» с целями, ценностями и направлениями;
- совместимость со старыми `Смыслами` и `goal_text` без потери данных;
- персональные проекции эффективности Триггеров и Замен по продукту и контексту.

### Доказательная база

- реестр источников;
- реестр проверяемых утверждений;
- связь утверждений с источниками;
- отдельный русский пользовательский слой Фактов и Мифов;
- ограничения и уровень доказательности;
- дата последней проверки и следующей ревизии;
- контекстная привязка материала;
- учёт показов и оценки полезности.

Стартовая база опирается преимущественно на материалы 2023–2025 годов и актуальные клинические рекомендации. Более старые источники допускаются только когда остаются наиболее сильным актуальным основанием для конкретного утверждения.

### Админский контур

Маршрут `/admin`:

- доступ только для `profiles.role = admin`;
- активные пользователи;
- использование сценария тяги;
- доля эпизодов без целевого употребления;
- повторное использование;
- когортная воронка новых пользователей;
- результаты по сигаретам / электронке / кальяну;
- структурированные причины остановки;
- востребованность Фактов и Мифов;
- состояние доказательной базы;
- технические ошибки;
- 95-й процентиль времени ответа, когда клиентская телеметрия начнёт его передавать.

Админка не читает private notes, тексты личного «Зачем» или содержимое чужих Связок.

## Локализация

Весь пользовательский и админский язык — русский.

Технические идентификаторы в коде/БД могут оставаться машинными и не выводятся пользователю.

## Что намеренно не входит

- полный редизайн текущего пользовательского интерфейса под новую стратегию;
- миграция всех экранов `Смыслы → Зачем`;
- новый runtime Intervention Engine;
- local LLM;
- Tribute;
- referral;
- применение schema migrations к production/alpha без отдельного validation gate.

## Зависимость

R1 основан на strategy foundation из `agent/product-strategy-foundation` и должен рассматриваться как stacked release до merge foundation PR.
