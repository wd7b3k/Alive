# Админский контур продуктовой аналитики ALIVE

## Назначение

Админский контур нужен не для чтения личной жизни пользователей, а для ответа на четыре вопроса:

1. пользуются ли ALIVE в реальных моментах тяги;
2. где пользовательская воронка ломается;
3. какие механики действительно связаны с полезным поведенческим результатом;
4. здоров ли технически продукт.

## Принцип

Админка строится одновременно с продуктовым ядром, а не после него. Любая новая ключевая механика должна иметь наблюдаемый вход, результат и причину отказа/незавершения.

## Пользовательская воронка

Базовая декомпозиция:

`регистрация → завершение первого знакомства → заполнение исходного уровня → первое Зачем → первая Связка → первый импульс → показ вмешательства → действие → результат → повторное использование → попытка отказа → устойчивый результат`

Для каждого перехода показывать:

- число пользователей;
- конверсию;
- медианное время до следующего шага;
- долю бросивших сценарий;
- технические ошибки;
- причины незавершения, если они известны из структурированных данных;
- разрезы по целевому продукту: сигареты, вейп, кальян.

## Метрики доказательства ценности

Главные:

- доля импульсов, не завершившихся целевым употреблением;
- изменение употребления относительно личного исходного уровня;
- доля пользователей, реально использующих ALIVE в момент тяги;
- изменение силы тяги до/после вмешательства;
- восстановление после эпизода употребления;
- доля повторно распознанных Связок;
- изменение силы убеждений/Мифов;
- эффективность Замен по контексту;
- рост интервалов без никотина для вейпа;
- достижение этапов отказа.

Ориентир результата — Sustained Freedom Rate, но в интерфейсе админки использовать только качественную русскую терминологию: «Устойчивая свобода от целевого продукта».

## Диагностика затыков

Админка должна позволять провалиться из общего падения конверсии до конкретного этапа и увидеть:

- на каком экране/действии произошёл выход;
- какой тип продукта был выбран;
- был ли известен триггер;
- было ли предложено релевантное вмешательство;
- была ли ошибка загрузки/записи;
- сколько времени занял ответ;
- не повторялся ли один и тот же контент слишком часто;
- не было ли слишком много действий в сценарии.

Никакие приватные заметки, тексты личного Зачем и свободные тексты Связок в обычную админскую аналитику не попадают.

## Контентная аналитика

Для каждого Триггера, Замены, Факта, Мифа и шаблона Зачем:

- показы;
- использование;
- пропуски;
- полезность;
- изменение тяги;
- доля эпизодов без употребления;
- повторное использование;
- контексты, где работает лучше/хуже;
- дата последней проверки доказательности для Фактов/Мифов.

## Техническое здоровье

- ошибки API;
- ошибки БД;
- ошибки авторизации;
- p50/p95 времени ответа ключевых сценариев;
- неуспешные записи событий;
- сбои пересчёта производных метрик;
- ошибки RLS/авторизации;
- состояние фоновых задач;
- последняя успешная проверка/агрегация.

## Локализация

Весь пользовательский и админский интерфейс — на русском языке. Не использовать англоязычные названия сущностей, метрик или статусов в интерфейсе. Технические идентификаторы внутри кода/БД могут оставаться машинными и не показываются пользователю.
