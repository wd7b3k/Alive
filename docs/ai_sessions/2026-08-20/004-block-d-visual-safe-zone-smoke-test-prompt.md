# Prompt — блок D: визуальный safe-zone smoke-test без живого логина

Дата: 2026-08-20

## Контекст

Продолжение после блока C (сессия 003, запушен и подтверждён). Владелец:

> пошли дальше и приближай релиз

Ранее было явно оговорено (и подтверждено самим владельцем через "Ну его нафиг...
Реши её самостоятельно... доведи меня до релиза"), что блок D
(`docs/V3_VISUAL_UX_BASELINE.md` — визуальный parity/safe-zone review по всем
экранам) требует реального Google-логина, которого у AI нет ни в облачной
песочнице, ни через мост к устройству владельца.

## Требования

Сделать максимум из блока D, что реально достижимо **без** живого логина:

- production production-домен (`alive-aw2.pages.dev`) недоступен напрямую из
  облачной песочницы (allowlist сети) и нет подключённого Chrome-браузера через
  `mcp__claude-in-chrome__*` (`list_connected_browsers` вернул пустой список) —
  найти альтернативный, но честный способ реального (не воображаемого) визуального
  теста;
- локально собрать `app/dist` из текущего коммита и прогнать реальный браузер
  (Playwright + предустановленный Chromium) на 5 обязательных ширинах из
  `docs/V3_VISUAL_UX_BASELINE.md` (360 / 390–430 / 768–820 / 1280 / 1440+);
- честно ограничить scope: без реального логина видны только экраны ДО
  аутентификации (Google login, `/experiment`, `/releases`) — весь список
  "Screen-level acceptance" в baseline (Today, guided craving flow, Links, Path,
  Meanings, Profile, evening check-in и т.д.) остаётся непройденным и не должен
  выдаваться за пройденный;
- любую найденную и воспроизводимую техническую (не продуктовую) проблему —
  чинить напрямую, если фикс безопасный, локальный и не требует владельческого
  решения; иначе — фиксировать как находку, не трогая.
- не объявлять релиз; не выдавать частичный локальный тест за полный acceptance.
