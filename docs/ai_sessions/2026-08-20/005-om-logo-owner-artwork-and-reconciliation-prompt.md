# Prompt — Om/ALIVE лого от владельца + сверка с block-a/b/c

Дата: 2026-08-20 / 2026-08-21

## Контекст

Отдельный от block-a/b/c поток: владелец попросил AI сформулировать промт для
полной визуальной переработки приложения к релизу, затем явно попросил
"делай свой промт" — то есть выполнить его напрямую в реальном репозитории, а
не просто выдать текст промта.

## Требования (последовательно, по мере разговора)

- полная визуальная переработка: минимализм, лучшие паттерны UI/UX, графические
  элементы бренд-стиля, максимальная адаптация под мобильные экраны;
- отдельно, прямой командой: "Сделай новый лого сам, там должно быть слово
  alive и символ Аум в едином стиле на точке смешения традиционных восточных
  форм и современного искусства" — AI сгенерировал собственный Om-глиф
  (PIL/cairosvg, параметрические arc-обводки);
- владелец прислал референсные изображения ("лого нужно в таком духе") и после
  того как увидел AI-вариант, отклонил его прямым текстом ("твой лого -
  катастрофическое дерьмо") и явно распорядился: использовать именно
  присланное им изображение, с адаптацией под экраны и разрешения — не
  дорисовывать, не заменять;
- дать команды для публикации в репозиторий;
- по мере попыток владельца выполнить команды на его Windows-машине (PowerShell)
  вскрылось: `.git/HEAD.lock`, затем устойчивый `.git/index.lock`,
  несуществующий локально `gh`, ветка, создавшая себя не в том состоянии из-за
  ранее упавшего `checkout -b`, CRLF-шум в `git status`;
- в процессе диагностики через мост к устройству владельца обнаружилось, что
  реальный репозиторий уже продвинулся через отдельный, не связанный с этой
  сессией поток работы: `docs/ai-session-2026-08-20-strategy-audit` →
  `docs/audit-followup-block-a-b` → `docs/audit-followup-block-c`, который
  частично пересекается с независимо найденными этой сессией дефектами (dead
  code, touch targets, sticky action safe-zone);
- финальная прямая команда владельца: "дай мне команды, сам сделаю" — то есть
  вместо дальнейшей автоматической правки через мост к устройству, подготовить
  корректный набор изменений и команд для владельца, основанный на РЕАЛЬНОМ
  текущем состоянии репозитория (`docs/audit-followup-block-c`), а не на
  устаревшей ветке от `main`.

## Ограничения (из AGENTS.md)

- brand-identity изменения требуют прямой команды владельца — получена явно и
  дважды (сначала "сделай сам", затем явный откат к присланному владельцем
  изображению);
- AI не подменяет ассет и не переписывает канонический хэш самостоятельно без
  решения владельца — в данном случае решение владельца прямое и
  недвусмысленное;
- push из облачной песочницы в `wd7b3k/Alive` заблокирован git-прокси сессии —
  единственный путь публикации отсюда — патч/явные команды для владельца.
