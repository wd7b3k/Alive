## Контекст

Продолжение сессии `001-objective-strategy-and-repo-audit`. Владелец сначала передал
находки аудита агенту DeepSeek (через Cline, локально) для исполнения по промту

> меня до релиза.

## Требования

Выполнить блоки A и B из `deepseek-dev-prompt-2026-08-20.md` самостоятельно:

- Блок A (документация, низкий риск): инвентаризация веток в
  `docs/INFRASTRUCTURE_STATE.md`; исправление branch-name drift в
  `docs/CURRENT_STATE.md`/`docs/INFRASTRUCTURE_STATE.md`; README-ссылки на три
  blocking-документа; добавление отсутствующей строки UGC-consent в
  `releases/v3.0-platform/VALIDATION.md`.
- Блок B (код, низкий-средний риск): повторно проверить и удалить мёртвый код
  (`App.tsx`, `visual-hardening.css`, `visual-polish.css`), если подтверждается;
  зафиксировать расхождение Om-asset SHA-256 как открытый вопрос, не подменяя ассет
  и не переписывая канонический хэш самостоятельно.

Блоки C (реальные privacy/security тесты против живого Supabase/Google OAuth) и D
(визуальный QA с реальным логином) явно оставлены за рамками этой сессии — они
требуют либо живых credentials, которых нет ни в облачной песочнице (есть сеть, нет
секретов), ни через мост к устройству владельца (есть доступ к файлам, нет сети) —
либо ручного прогона владельцем.

Релиз не объявляется — это решение владельца по `docs/RELEASE_POLICY.md`.
