# Prompt — трение внутри сценария тяги

Дата: 2026-08-26

## Постановка (аудит 26.08.2026, гипотеза для проверки, не установленный факт)

Управляемый флоу тяги («Меня тянет») требует минимум 4 полных шага с экранами выбора
(продукт → контекст, выбор из 15+ карточек → потребность → замена → результат), при том
что собственные принципы продукта прямо требуют обратного — P17
(`docs/PRODUCT_PRINCIPLES.md`: «Минимум действий в момент тяги. Craving flow должен быть
максимально коротким») и гипотеза `H-ALIVE-005` (`docs/HYPOTHESES_AND_METRICS.md`) о
понятности продукта без устного объяснения автора.

## Задача

Сократить трение внутри существующих 4 шагов, не переписывая саму методологию (порядок
ситуация → потребность → ответ → результат остаётся неизменным):

- смарт-дефолт по последнему использованному продукту — пропускать шаг его выбора, если
  последние N раз он один и тот же;
- поднять 3–5 самых частых по личной истории триггеров на верх сетки контекстов вместо
  фиксированного порядка;
- рассмотреть схлопывание шага «потребность» в короткую подпись под уже выбранным
  контекстом там, где система уже уверена по истории, вместо отдельного полного экрана
  выбора.

Точный набор решений — на усмотрение сессии, с опорой на P3 (progressive disclosure) и
P17 из `docs/PRODUCT_PRINCIPLES.md`.

## Ограничения, которые нельзя нарушать

- не убирать шаг фиксации результата — он источник данных для метрик `H-ALIVE-001`
  (successful response rate, target usage vs baseline, craving delta);
- не менять сам порядок ситуация → потребность → ответ → результат;
- оставаться в рамках утверждённых принципов P1–P20, не изобретать новые паттерны вроде
  геймификации скорости в процессе «ускорения» флоу;
- не понижать доступность: touch-таргеты остаются ≥44×44pt.

## Порядок работы

1. Замерить текущее количество кликов/экранов до завершения на 3–5 самых частых
   сценариях.
2. Спроектировать и реализовать сокращения по одному, проверяя каждое отдельно.
3. Повторно замерить те же сценарии.
4. Подтвердить, что метрики `H-ALIVE-001` остаются измеримыми (шаг результата не потерян
   ни в одном сценарии, включая сокращённые).

## Уточнения владельца

Форма сдачи — отдельная ветка и коммит.

Глубина схлопывания шага «потребность» — «подпись + возможность изменить»: если по
истории для пары продукт + контекст одна потребность доминирует, отдельный экран не
показывается, потребность подставляется подписью со ссылкой «изменить», ползунок силы
тяги переезжает на шаг ответа. Порядок методологии сохраняется, состав записи эпизода не
меняется.
