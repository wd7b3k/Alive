## 1. Авторизация убрана с первого экрана

Первый экран был стеной входа: без сессии показывался только логин. Чтобы открыть
интерфейс сразу, потребовалось решить не UI-задачу, а задачу доступа — все каталоги
читались только ролью `authenticated`, и анонимный посетитель увидел бы пустые полки.

Сделано:

- `app/src/data.ts` — тип `PublicCatalog` и `loadPublicCatalog()`, читающий только
  опубликованный редакционный каталог и не требующий сессии;
- `app/src/RedesignApp.tsx` — `PublicHome` и `startGoogleSignIn()`; роутер пропускает
  `/experiment` и `/releases` без сессии и отдаёт `PublicHome` вместо логина на `/`.
  Загрузка публичного каталога никогда не блокирует страницу: падение запроса не
  превращается в пустой экран;
- миграция `20260822120000_v3_public_catalog_read_for_anon.sql` — `select` для `anon`
  на восьми редакционных каталогах, каждая политика фильтрует `published = true`.

Граница проведена сознательно узко и **закреплена автотестом**, а не намерением:
`supabase/tests/local/03_rls_isolation_test.sql` теперь ассертит, что `anon` читает
каталоги и **ноль строк** в 11 приватных таблицах. Если будущая миграция расширит
анонимный доступ, тест упадёт.

Тест сам себя поймал на ошибке: первая версия использовала `set local role anon` вне
транзакции — это no-op, запрос выполнялся суперпользователем и «нашёл» несуществующую
утечку в 2 строки. Исправлено на `set role`. Записываю это как работу теста, а не как
найденную утечку.

Проверено на живом проде анонимным ключом: каталоги читаются (28 триггеров, 74 замены,
13 Смыслов, 106 связей), `episodes` / `profiles` / `user_meanings` — 0 строк.

## 2. Edge Function удаления аккаунта задеплоена

`supabase/functions/delete-account/index.ts` задеплоена через дашборд (Edge Functions →
Via Editor). Негативный тест выполнен мной: `POST /functions/v1/delete-account` без
сессии → `401 {"error":"authentication_required"}`, причём строка ошибки — из кода
функции, а не из шлюза, то есть функция реально исполняется и **fails closed**.
Позитивный тест я намеренно не запускал (необратимое уничтожение аккаунта); владелец
прогнал его 2026-08-22 на одноразовом аккаунте — удаление срабатывает.

## 3. Контентные решения владельца

Миграция `20260822130000_v3_tension_mappings_and_meaning_titles.sql`:

- `tension` («Напряжение / сложная мысль») — один из самых частых реальных триггеров —
  не имел **ни одной** курированной связи, и `pickReplacements` молча падал на подбор
  по потребности. Добавлено 5 связей: дыхание → снятие мышечного напряжения → движение
  → смысл. Столько же для `after_task`. Нового контента не выдумано: все связи ведут на
  уже существующие замены, тиры повторяют соглашение соседнего `anxiety`;
- `other` («Другое») оставлен без связей осознанно: это catch-all для ситуации, которую
  человек не смог назвать, — курировать здесь нечего, fallback по потребности корректен
  по замыслу. Это записано в самой миграции, чтобы следующий читатель не принял это за
  пропуск;
- `meaning_read` и `meaning_card` в проде назывались одинаково после переименования
  терминологии, из-за чего в одной тройке могли оказаться две визуально идентичные
  карточки. Переименованы так, чтобы название говорило, чем они отличаются:
  «Перечитать своё «Зачем»» (весь список) и «Одна опора из «Зачем»» (одна формулировка
  на сегодня). Ни одна из них не удалена — это разные действия;
- дополнительное подтверждение для «Предложить в общую базу» не добавлено по решению
  владельца: сама явно подписанная кнопка и есть требуемое явное действие.

## 4. Визуальная правка

Отложенная в прошлом проходе находка закрыта: `.r-reading` имел `width:calc(100% - 24px)`
и `-18px`, из-за чего бренд-кнопка отступала от края на ~12px при baseline-минимуме 16px.
Обе величины приведены к `-32px`. Измерено Playwright'ом на реальной сборке: 360/390/414 —
отступ 37px, horizontal overflow 0, регрессий на 768/1280/1440 нет.

Правка была отложена именно потому, что задевает каркас, общий с экранами за логином;
внесена только после того, как владелец подтвердил эти экраны на живом устройстве.

## 5. Docker

Демон в песочнице поднимается (`sudo dockerd`), но все реестры образов закрыты сетевым
allowlist — ни один образ не тянется. Запустить стек Supabase CLI по-прежнему нельзя.
Оставляю два соответствующих пункта `VALIDATION.md` непройденными честно, вместо того
чтобы выдать локальный Postgres за CLI-стек. Существо пункта закрыто иначе: база из
миграций побайтово воспроизводит прод (совпадение агрегатных SHA-256), и миграции
прогоняются на чистой Postgres в CI на каждый PR.
