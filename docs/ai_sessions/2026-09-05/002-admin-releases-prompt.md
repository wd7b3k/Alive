**T-20260905-01 · Внутренний раздел «Что сделано» по адресу /admin/releases**

Тема: release · Ветка: task/T-20260905-01 · Статус: todo

**0. Прежде чем писать код.** Задача — развитие существующей админки, а не новый раздел с
нуля. Прочитать фактическое состояние, не полагаться на этот текст там, где он расходится
с кодом: `docs/NAVIGATOR.md`, `AGENTS.md`, `docs/tasks/README.md`, `docs/tasks/TEMPLATE.md`;
`app/src/redesign/admin.tsx` — оболочка админки, `ADMIN_SECTIONS`, правило в шапке файла
про источник данных, проверка роли; `app/src/modules/analytics/` и раздел
`/admin/monitoring` — как устроен уже работающий раздел админки: загрузка, состояния
«пусто / не посчитано / ошибка»; `app/src/redesign/releases.ts` и `releases.test.ts` —
публичный `/releases`; `app/vite.config.ts` (`prerenderPublicRoutes`),
`app/src/services/prerender.ts`, `infra/caddy/Caddyfile`, `caddy-routes.test.ts` — списки
адресов, которые придётся дополнить; `scripts/check-deploy-drift.mjs`,
`scripts/check-local-drift.mjs`, `scripts/tasks.mjs` — уже написанные разборы git и сверка
с продом, повторно не изобретать; `docs/board/cards.json`, `docs/tasks/` — куда указывают
трейлеры коммитов; `docs/DESIGN_SYSTEM.md`, `docs/BRANDBOOK.md`, `docs/TONE_OF_VOICE.md`;
`docs/decisions/` — найти первый свободный номер ADR (0017 занят базой знаний).

Если что-то из перечисленного отсутствует или называется иначе — действовать по факту
репозитория и записать расхождение в итоговой записи сессии.

Публичный `/releases` не трогать. Его формат — заголовок и один абзац на версию, это
решение от 27.08 с удалённым полем `changes`. Новый раздел живёт отдельно, по другому
адресу, для другого читателя (владелец), и никаким образом не связан с `releases.ts`.

**1. Зачем.** Сейчас ответ на вопрос «что уже внедрено» собирается вручную из записей
сессий, карточек доски и памяти. Записи расходятся между собой (три противоречивых
утверждения о бэкапах за четыре дня — ровно этот случай). Нужен один экран, который
отвечает на этот вопрос по факту кода, а не по чьему-то пересказу: всё, что уехало на
прод, со ссылкой на коммит. Раздел внутренний: читатель — владелец, задача —
проверяемость и полнота, а не человеческая формулировка.

**2. Решение по источнику данных.** Список строится из git на сборке. Ручного реестра
нет — он отстанет на первой же неделе. Скрипт `scripts/build-changelog.mjs`, без внешних
зависимостей, запускается перед `vite build` (шаг `prebuild` или явный вызов в скрипте
сборки — как принято в `app/package.json`). Пишет `app/src/generated/changelog.json`, файл
в `.gitignore`.

Что кладёт в запись коммита:

| Поле | Откуда |
|---|---|
| полный и короткий отпечаток, дата автора, автор | `git log --format` одним вызовом, с разделителем, который не встречается в тексте |
| заголовок и тело сообщения | оттуда же |
| тема | из изменённых путей по карте «путь → тема», темы совпадают со списком доски: `infra process design content pilot seo brand perf release auth flow privacy money legal knowledge social` |
| карточка доски | трейлер `Board: done <id>` в теле; по нему — заголовок и эпик из `docs/board/cards.json` |
| задача | файл `docs/tasks/T-<id>*.md`, если он есть и упомянут |
| номер PR | из заголовка merge-коммита `Merge pull request #NN` |
| метка «миграция» | коммит трогает `supabase/migrations/` |
| версия | значение `version` из `package.json` на момент коммита |

Классификация по типу (появилось / починено / документация / инфраструктура) — эвристика
по путям и глаголам заголовка. Она называется эвристикой в интерфейсе (правило
`AGENTS.md`), а не выдаётся за факт; коммит с трейлером `Board:` берёт тип из карточки и
помечается как достоверный.

Версии считать так: одним запросом получить коммиты, менявшие `package.json`, для каждого
прочитать `git show <sha>:package.json` и взять `version`; остальные коммиты попадают в
интервал между соседними значениями. Не читать `package.json` на каждом коммите — это
сотни лишних вызовов.

Если git недоступен в контексте сборки — сборка не падает. Скрипт пишет файл с полем
`unavailable` и причиной, раздел показывает причину, а не пустой список (правило витрин:
непосчитанное возвращает причину, а не ноль).

**3. Что раздел говорит о проде.** Раздел открывается на проде, значит его собственный
`changelog.json` — это по построению ровно то, что на проде выложено. Из этого и исходить,
ничего не выдумывая: шапка раздела показывает отпечаток и время сборки (те же, что в
`version.json`); при открытии раздел запрашивает `/version.json` с уникальным параметром
строки запроса и `cache: 'no-store'` (ловушка 27.08: кеш на пути запроса отдавал сборку
семичасовой давности) и сравнивает отпечаток с собственным — расходится, строка «открыта
не та сборка, что отдаёт сервер: `<a>` против `<b>`, обновите страницу»; одной строкой
честно сказано: коммиты, влитые в main после этой сборки, здесь не видны по построению,
сверка main ↔ прод — это `scripts/check-deploy-drift.mjs`.

Никаких обращений к GitHub API из браузера: репозиторий приватный, токену в клиенте не
место, инвариант «никаких внешних сервисов в рантайме» здесь остаётся в силе. Ссылки на
коммиты — статические, базовый адрес репозитория задаётся одним значением в конфигурации
(`VITE_REPO_URL`, значение по умолчанию `https://github.com/wd7b3k/Alive`), а не строкой в
разметке.

**4. Интерфейс.** Пункт в `ADMIN_SECTIONS`: `id: 'releases'`, `title: 'Что сделано'`,
`status: 'live'`, адрес `/admin/releases`. Раздел уезжает в существующий чанк админки,
отдельного входа в приложение не создаёт.

- Группировка по версиям, сверху — «Не выпущено» (коммиты после последнего изменения
  `version`), затем 3.2, 3.1 и ниже. В шапке версии: число изменений, даты первого и
  последнего коммита, число миграций.
- Строка изменения: тип, тема, заголовок сообщения, дата, короткий отпечаток моноширинным
  — ссылка на коммит (`target="_blank"`, `rel="noreferrer"`). Если есть карточка, задача
  или PR — ссылки на них. Метка миграции видна сразу.
- Раскрытие строки: тело сообщения, затронутые каталоги, все связанные ссылки.
- Фильтры: тема, тип, «только миграции», поиск по заголовку и телу. Фильтры в адресе
  строки запроса, чтобы состояние можно было переслать себе же.
- Тексты — по `TONE_OF_VOICE.md`, латиницы в интерфейсных надписях нет (кроме отпечатков,
  имён файлов и путей). Проверить на 390 и 1280, ширины 320–1600 не ломать.

**5. Инварианты.**

- Раздел не публичный: нет в `prerenderPublicRoutes`, нет в `sitemap.xml`, `noindex`,
  доступ только роли `admin` — тем же механизмом, что `/admin/analytics`, без своей
  проверки роли.
- Публичный `/releases`, `releases.ts` и `releases.test.ts` не изменяются ни одной строкой.
- `app/src/generated/` — генерируемое, в git не попадает; в CI генерируется тем же скриптом.
- Правило админки «данные только через функции `admin_*`» здесь не применяется: данных нет
  в базе, источник — репозиторий. Это исключение записать явно в шапке раздела и в ADR, а
  не оставить молча нарушенным.
- Риск, который надо зафиксировать в ADR, а не обойти молчанием: сообщения коммитов
  приватного репозитория уезжают в статический ассет сборки, доступный по прямой ссылке
  любому, кто её знает. Принимается сознательно: сообщения — рабочий текст, не секрет. Если
  владелец решит иначе — альтернатива в том, чтобы отдавать список функцией
  `admin_releases` из базы, с загрузкой на выкладке; это дороже на один серверный шаг при
  каждом деплое и в эту задачу не входит.
- Основной чанк не растёт. Чанк админки — измерить до и после, число назвать в записи
  сессии.

**6. Приёмка.**

- `tsc --noEmit`, `eslint`, `prettier --check`, `vitest run` — зелено, существующие тесты
  не переписаны под новое поведение.
- Новые тесты: разбор вывода `git log` на фикстуре (трейлер `Board:`, номер PR, тема по
  путям, интервалы версий, коммит без всего этого); отсутствие git при сборке не роняет её
  и даёт файл с причиной; `/admin/releases` отсутствует в списке публичных адресов и в
  `sitemap.xml`; `caddy-routes.test.ts` проходит с новым адресом.
- Скриншоты раздела на 390 и 1280, свёрнутое и раскрытое изменение.
- Сборка проверена на реальной истории репозитория: число записей совпадает с
  `git rev-list --count HEAD`, ни один коммит не потерян и не задвоен.
