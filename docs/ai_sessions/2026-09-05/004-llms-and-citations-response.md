# `llms.txt` из каталога и источник у каждого ответа

Работа по `HANDOFF.md` от 05.09.2026. Ветки `seo/llms-from-catalog` (PR #80) и
`seo/faq-citations` (PR #81) — обе влиты, прод на `7420928`.

Предыдущая задача (`X-Robots-Tag`) проверена перед началом: влита и выложена,
`check-deploy-drift.mjs` выходил нулём, заголовок на `/profile` на месте.

## 1. `llms.txt` собирается из каталога

Файл описывал продукт, которого уже нет. И одно из чисел было просто неправдой:
**«28 пусковых моментов» против 25 опубликованных в базе.**

Теперь его кладёт тот же скрипт, что снимает выгрузку каталога. Три производных файла:
`app/knowledge-catalog.json` (карточки), `app/catalog-counts.json` (числа по остальным
каталогам — отдельным файлом, потому что это другой вопрос) и `app/public/llms.txt`.

```
$ curl -s https://habitoff.ru/llms.txt
адресов карточек: 38
разделы: Как устроена доказательная база · Факты (19) ·
         Разобранные убеждения (19) · Что ещё можно цитировать · Чего в продукте нет
три запретных утверждения: 3
старое число «28 пусковых»: 0

повторный прогон на неизменившемся каталоге — побайтно тот же файл
--check на неизменённом  → код 0
--check на изменённом    → «app/public/llms.txt: разошёлся с базой», код 1
```

Три запретных утверждения сохранены дословно и проверяются дословно: это единственное
место, где продукт говорит моделям, чего ему приписывать нельзя, и пересказ своими
словами здесь равен потере.

### `llms-full.txt` — решено не делать

Решение опирается на журнал, а не на общие соображения. В журнале Caddy за всё время
**два** обращения к `llms.txt`, а `GPTBot`, `ClaudeBot` и `PerplexityBot` не заходили на
домен **ни разу**: из ботов приходили только Googlebot (186 обращений) и YandexBot (102).

Полный текст всех карточек уже лежит на их собственных страницах, и `llms.txt` ведёт на
каждую абсолютным адресом. Третья копия тех же текстов ради аудитории, которая пока не
появилась, добавила бы 50 КБ и ещё один файл, который надо держать честным. Появится —
добавить дёшево, тем же скриптом и с той же проверкой.

## 2. Источник у каждого ответа

`FAQPage` на главной нёс пять утверждений о здоровье и ни одного `citation`. То же
правило, которое в базе держит триггер, в разметке не действовало.

Источники берутся из карточек каталога — все пять вопросов пересказывают опубликованные
карточки, искать заново было нечего. Тексты вопросов остались в `index.html`, где их
писали; сопоставление хранит только коды (`FAQ_SOURCES` в `schema.ts`), второй копии
текста не заведено. Вопрос без карточки роняет сборку и называет вопрос: решать, найти
ему карточку или убрать из разметки, должен человек, а не сборка молча.

```
$ curl -s https://habitoff.ru/
вопросов: 5 | без citation: 0 | вопросов только в разметке: 0

валидатор Schema.org — https://habitoff.ru/
  ошибок: 0 | предупреждений: 0
  WebSite×1, WebApplication×1, Offer×1, FAQPage×1, Question×5, Answer×5, CreativeWork×5
```

### Что вскрылось попутно

**Два вопроса из пяти стояли в разметке и отсутствовали в видимом тексте главной** —
про вейп и про кальян. Это ровно то расхождение, ради которого 05.09 вводилось правило
«разметка не описывает того, чего нет на странице», и исключений для главной оно не
делает. Вопросы добавлены в текст; поймал это новый тест, а не глаз.

**Число 28 живёт не только в `llms.txt`.** Оно же стоит в описании `/links` в `seo.ts` и
в статическом тексте главной — то есть на живых страницах. Поправил на 25, но это опять
ручное число: правильное место для него — генерация, как уже сделано для `llms.txt`.
Заведена карточка `chisla-v-index-html`.
