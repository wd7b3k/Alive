## 2. Разметка по месту

`FAQPage` теперь ровно на одном адресе, и это видно снаружи:

```
/                   FAQPage:1 Breadcrumb:0 ItemList:0
/knowledge          FAQPage:0 Breadcrumb:1 ItemList:1
/links              FAQPage:0 Breadcrumb:1 ItemList:0
/meanings           FAQPage:0 Breadcrumb:1 ItemList:0
/experiment         FAQPage:0 Breadcrumb:1 ItemList:0
/releases           FAQPage:0 Breadcrumb:1 ItemList:0
/net-takogo-адреса  FAQPage:0 Breadcrumb:0 ItemList:0
```

Валидатор Schema.org по живому адресу:

```
валидатор Schema.org — https://habitoff.ru/knowledge
  totalNumErrors  : 0
  totalNumWarnings: 0
  типов: CollectionPage×1, BreadcrumbList×1, ListItem×18, ItemList×1,
         Question×16, Answer×16, CreativeWork×17
  вопросов: 16 | без citation: 0 | с doi: 6
```

**Шестнадцать из девятнадцати — и это не потеря, а фильтр.** Три мифа ссылаются на
`docs/METHODOLOGY.md`, то есть на нас самих: это рабочие эвристики проекта, `AGENTS.md`
требует называть их эвристиками, а не выдавать за доказанное. Сослаться на себя не значит
сослаться, и в сниппет выдачи такое утверждение уходить не должно.

**Откуда берутся тексты — и почему не из репозитория.** Каталог правят миграции: только
по мифам их одиннадцать, и часть переписывала формулировки целиком; в живой базе у
`myths_catalog` уже нет колонки `source_url` — источники нормализованы в отдельную
таблицу. Восстановить текущее состояние разбором SQL нельзя, а копия в git разошлась бы
с базой на следующей миграции — и расхождение уехало бы в сниппет и в пересказ языковой
модели, где его никто не проверит.

Поэтому источник разметки — сама база, а выгрузка (`scripts/dump-knowledge-for-schema.mjs`)
делается на выкладке. `app/knowledge-schema.json` в git не попадает. Базы нет — нет
`ItemList`, остальная разметка от него не зависит; так собирается CI.

## Найдено попутно: вторая копия, которая молча устарела

Первая выкладка после влития разметки собралась **без источников**, и по логу это было
не видно. Причина: `/srv/alive/deploy.sh` — копия файла из репозитория, и в неё не попал
новый шаг выгрузки каталога. Тот же класс, что и с `Caddyfile`: канонический файл в git,
рабочий — копия на сервере, и между ними нет ничего, что бы их сверяло.

Теперь выкладка сверяет себя с `infra/deploy/deploy.sh` и отказывается работать
устаревшей копией. Проверено подменой:

```
ОТКАЗ: установленный /srv/alive/deploy.sh отличается от …/infra/deploy/deploy.sh.
  Копия устарела — обнови её и повтори: …
код возврата: 1
СИМЛИНК НЕ ТРОНУТ
```

Сама себя копия не переустанавливает: менять файл, из которого читается текущая команда,
посреди выкладки — не то, что стоит делать автоматически.
