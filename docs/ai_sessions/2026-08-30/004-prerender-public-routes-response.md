# Пять адресов перестали быть одной страницей

Ответ на `004-prerender-public-routes-prompt.md`. Ветка
`feat/prerender-public-routes` от `origin/main` = `43b10e1`.

## Что было

Проверено сравнением собранных файлов, а не описанием: до правки `dist/` содержал один
`index.html`, и все пять адресов из карты сайта отдавали его же. Внутри —
`<link rel="canonical" href="https://habitoff.ru/">`. Карта сайта звала по адресам,
каждый из которых сам себя объявлял копией главной.

## Что сделано

**Плагин `habitoff-prerender-routes`** (`app/vite.config.ts`). Работает на `writeBundle`:
к этому моменту `index.html` уже прошёл преобразования Vite и содержит финальные имена
чанков, поэтому копии отличаются ровно тем, чем должны. Чистая часть вынесена в
`app/src/services/prerender.ts` — её видит тест.

**Второй копии заголовков нет.** `PRERENDER_PATHS` выводится из `PAGES` в
`app/src/services/seo.ts` фильтром «не главная и не noindex», значения тегов берутся
через `metaFor(path)`. Новый публичный раздел получает предрендер тем же движением,
каким получает заголовок. Если тега нет в шаблоне — сборка падает: страница с чужим
canonical обнаружилась бы через месяц в выдаче, а не на сборке.

**`/releases` отдаёт тексты.** Единственная страница, содержание которой известно на
этапе сборки: константа `RELEASES`, а не запрос к базе. Разделы, живущие данными, копии
не получили — правило `docs/SEO_AND_ANALYTICS.md` («копия, которая расходится с базой,
хуже её отсутствия») осталось в силе, и на это есть отдельный тест.

**`sitemap.xml` собирается.** Появились `/releases` и `lastmod` у всех адресов. Дата
берётся из git по файлам, из которых страница фактически собрана, — пересборка без
коммита её не двигает. `changefreq` и `priority` убраны: поисковики их не читают.

**`robots.txt`.** Запреты повторены в каждой группе (группы не складываются), добавлены
`/admin` и `/login`, директива `Host` убрана. `services/robots.test.ts` сверяет файл со
списком `NOINDEX_PATHS` из `seo.ts`.

## Проверка

`npm run build`, затем по собранному каталогу:

```
$ for p in "" knowledge links meanings experiment releases; do ... done
/              15719eb92a57ab7f 13911
/knowledge     e72d621a0b4cafde 13594
/links         c715b36ffb3f557a 13578
/meanings      c20f7cc62555dbd5 13586
/experiment    612005f3220e4bfc 13526
/releases      6727353775d89447 10690

$ grep -o 'canonical" href="[^"]*"' dist/knowledge/index.html
canonical" href="https://habitoff.ru/knowledge"
```

Шесть разных SHA-256 там, где был один. Тексты всех четырёх версий лежат в
`dist/releases/index.html` статикой.

`npm run format:check`, `npm run lint`, `npm test` — 21 файл, 186 тестов, все проходят.
Из них новые: 9 проверок предрендера и 4 проверки `robots.txt`.

## Чего эта сессия не проверила

Приёмка на живом домене (`curl -s https://habitoff.ru/knowledge | grep canonical`)
требует выкладки, а выкладка идёт из `main`. Она снимается после merge — и вместе с
сессией C, которая кладёт в репозиторий конфигурацию веб-сервера: именно она решает,
отдаст ли Caddy `knowledge/index.html` на адрес `/knowledge`. Порядок задан владельцем
и не нарушен: C идёт после A, иначе предрендеренные адреса начали бы отдавать 404.
