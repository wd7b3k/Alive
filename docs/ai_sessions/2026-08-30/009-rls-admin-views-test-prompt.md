# Три задачи вечера: Caddy, отпечаток сборки, красный CI

Запрос владельца, 30.08.2026, вечер. Передан файлом `HANDOFF.md` во временной рабочей
копии — задание составлял ассистент без доступа к серверу, файл удаляется последним
действием сессии и в git не попадает.

Состояние на момент постановки (по замеру снаружи, сделанному автором задания):

- `origin/main` = `8afbce4`, PR #47 влит;
- живой прод отдаёт `version.json` с пустым `commit`, сборка от 30.08 18:02;
- `/`, `/knowledge`, `/releases` отдают побайтно одно тело, canonical везде на главную;
- CI на `main` красный.

Причина выкладки 18:02 уже установлена: владелец сам запустил `/srv/alive/deploy.sh` из
консоли Timeweb под root, git внутри упал с `detected dubious ownership`, отпечаток вышел
пустым.

## Задача 1. Применить конфигурацию Caddy на прод

Порядок — `infra/caddy/README.md`. Ключ `sb_publishable_…` взять из действующего
`/etc/caddy/Caddyfile` до его замены. Git-команды на сервере выполнять от владельца
каталога, не от root. После установки обязательно проверить вход через Яндекс: он
единственный зависит от подстановки заголовка и ломается молча.

## Задача 2. Вернуть сборке отпечаток

Выкладка из репозитория. Приёмка: `version.json` отдаёт commit, равный `origin/main`;
`check-deploy-drift.mjs` выходит нулём; SHA-256 тел `/`, `/knowledge`, `/releases`
различаются; canonical на `/knowledge` свой; в `/releases` без JS видны тексты релизов;
`Cache-Control` на `/assets/*` не `no-cache`; `/site.webmanifest` отдаётся с
`application/manifest+json`; несуществующий путь — 404, все адреса из `sitemap.xml` — 200.
Показать вывод каждой проверки, а не описание.

## Задача 3. Починить красный CI

Job `RLS cross-tenant isolation` падает с кодом 3:

```
psql:04_admin_views_test.sql:55: ERROR: admin_core_metrics доступна только
администраторам приложения
```

Тест зовёт витрину в локальной базе, где роль администратора не выставлена, и получает
ровно тот отказ, который функция обязана давать. Сломан тест, а не витрина: ему не
хватает шага, делающего тестового пользователя администратором, — как это сделано в
`supabase/tests/local/03_rls_isolation_test.sql`.

Приёмка: `bash supabase/tests/local/run.sh` проходит локально, прогон CI на ветке зелёный.

## Правила

Одна ветка на задачу, трейлеры `Board: done` и `Board: new` в тех же коммитах, в конце
`node scripts/board.mjs apply && node scripts/board.mjs md` и коммит
`board: применены трейлеры`, пара `docs/ai_sessions/`, пуш и PR. Прод правится только
выкладкой из репозитория. Секреты из `app/.env` и ключи не печатать. На сервере ничего не
удалять без явной нужды.
