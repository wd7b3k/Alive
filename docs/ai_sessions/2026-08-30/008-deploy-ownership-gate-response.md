# Гейт, который пропускал ровно то, ради чего написан

Ответ на `008-deploy-ownership-gate-prompt.md`. Ветка `fix/deploy-ownership-gate` от
`origin/main` = `95308c3`.

## Что оказалось не так в исходной картине

Одно уточнение к постановке, и оно меняет объём работы. **Предрендер на прод приехал.**
Проверено на живом сервере:

```
$ ls -l /srv/alive/current/knowledge/index.html
-rw-r--r-- 1 root root 14334 Aug 30 18:02 /srv/alive/current/knowledge/index.html
$ grep -o 'canonical" href="[^"]*"' /srv/alive/current/knowledge/index.html
canonical" href="https://habitoff.ru/knowledge"
```

Файл лежит на диске, canonical в нём правильный. Наружу он не выходит по другой причине:
в `/etc/caddy/Caddyfile` стоит `try_files {path} /index.html`, а эта форма не совпадает с
каталогом — `/knowledge` не находит файла, откатывается на общий `index.html`, и все
адреса отдают одно тело. Это не дефект выкладки и не лечится ею.

Значит из семи пунктов приёмки три (`SHA-256` тел различаются, canonical на
`/knowledge`, тексты релизов без JS) закрываются конфигурацией веб-сервера, а не этой
задачей. Она написана и лежит в PR #47 (`infra/caddy-config`), не влитом.

## Владелец каталога

```
$ stat -c "%U %G %a %n" /srv/alive/repo /srv/alive/repo/.git /srv/alive/current
alive alive 755 /srv/alive/repo
alive alive 775 /srv/alive/repo/.git
root  root  777 /srv/alive/current
```

Каталог принадлежит `alive` — под ним он создан и под ним работает выкладка. В самом
`.git` чужих файлов **не оказалось ни одного**: root не успел там ничего создать,
потому что git отказался работать раньше. Чужое лежало снаружи `.git` — 9525 файлов в
`app/node_modules` и `app/dist`, плюс каталог релиза `20260830-180257` и сам симлинк
`current`.

Отказ воспроизведён дословно:

```
$ sudo -n env -u SUDO_UID -u SUDO_USER git -C /srv/alive/repo rev-parse HEAD
fatal: detected dubious ownership in repository at '/srv/alive/repo'
```

Существенная деталь: `sudo deploy.sh` сохраняет `SUDO_UID`, и по нему git признаёт
каталог своим. Ломается не любой root, а запуск из root-сессии, где `SUDO_UID` нет.
Разбирать эти случаи по отдельности незачем — прав root выкладке не нужно ни для чего.

Владелец возвращён каталогу целиком (`chown -R alive:alive` на `repo`, релиз и симлинк).
Бэкапы в `/srv/alive/backups` намеренно оставлены root-овыми с правами 600 — так их
пишет `habitoff-backup`.

## Почему скрипт не остановился

Гейт грязного дерева был написан так:

```bash
[[ -z "$(git status --porcelain)" ]] || { echo "ОТКАЗ: рабочее дерево грязное"; exit 1; }
```

Упавший git пишет в stderr и не печатает в stdout ничего. Подстановка пуста, условие
истинно, гейт доволен. **Проверка пропускала ровно тот случай, ради которого написана:**
когда о состоянии дерева не известно ничего. `set -euo pipefail` тут не помогает —
неуспех подстановки внутри `[[ ]]` не считается неуспехом команды.

Дальше по цепочке: сборка собралась из того, что лежало в каталоге; плагин отпечатка
вызвал `git rev-parse HEAD`, получил исключение и записал пустую строку; симлинк
переключился; прод стал отдавать сборку без имени.

## Что сделано

`deploy.sh` внесён в репозиторий — `infra/deploy/deploy.sh`, до сегодня его в git не
было вовсе, и разобрать оборванную выкладку можно было только чтением файла по ssh.
Заодно это двигает `proc-no-manual-prod`: последний кусок прода, живший только на
сервере, кроме конфигурации Caddy, теперь версионируется.

Правило, которому подчинён весь файл: **ни одна команда не проверяется по своему выводу,
только по коду возврата.** Сверх этого:

- **от root не запускается вовсе.** Проверка стоит первой: она закрывает причину, а не
  следствие, и заодно вторую половину той же беды — `npm ci` и сборка от root оставляют
  в репозитории тысячи файлов чужого владельца;
- **сборка обязана быть подписана.** `dist/version.json` проверяется на непустой commit,
  равный `HEAD`. Ровно этого не хватило 30.08;
- **entry-чанк из `index.html` обязан лежать в `dist/assets`** — половина скопированной
  сборки выглядит как целая до первого запроса;
- **симлинк переключается последним действием.** Любой отказ до этого оставляет прод
  нетронутым, а незавершённая раскладка убирается за собой.

Порядок установки, разбор и способ проверить сам гейт — `infra/deploy/README.md`.
