# Вернуть выкладку: владелец каталога и гейт, который не сработал

Запрос владельца, 30.08.2026.

30.08 в 18:02 выкладка прошла наполовину. Все git-команды внутри неё упали с
`detected dubious ownership in repository at /srv/alive/repo` — root оставил в каталоге
файлы чужого владельца. При этом `deploy.sh` не остановился: собрал рабочее дерево как
есть и выложил. Живой прод: `version.json` с пустым `commit`, `/`, `/knowledge` и
`/releases` отдают один документ с canonical на главную.

1. Выяснить владельца `/srv/alive/repo`, найти файлы с другим владельцем, вернуть
   каталогу единого владельца. Не выбирать владельца наугад: брать того, под кем каталог
   создан и под кем работает выкладка. Если `deploy.sh` запускает git от root — это и
   есть причина, и чинить надо скрипт, а не только права.
2. Привести прод к `main`. Git-команды выполнять от владельца каталога, не от root,
   иначе поломка вернётся на следующей выкладке.
3. Главный дефект вечера: `deploy.sh` продолжил работу после падения git и выложил
   старое молча. Скрипт обязан падать на первой же неуспешной команде и не доходить до
   подмены симлинка. Исправить в репозитории, а не правкой файла на сервере — сейчас
   `deploy.sh` в git не отражён, значит сначала внести его в репозиторий, потом чинить.

Приёмка, показать вывод каждой: `version.json` отдаёт commit, равный `origin/main`;
`check-deploy-drift.mjs` выходит нулём; SHA-256 тел `/`, `/knowledge`, `/releases`
различаются; `curl /knowledge | grep canonical` → `/knowledge`; в `/releases` без JS
видны тексты релизов; `build_fingerprint` даёт `ok`; намеренно оборванная выкладка
завершается ненулевым кодом и не подменяет симлинк.

Правила: одна ветка на задачу, трейлеры в тех же коммитах, пара `docs/ai_sessions/`,
пуш и PR. Прод правится только выкладкой из репозитория. Секреты из `app/.env` не
читать и никуда не печатать. Ничего не удалять на сервере без явной нужды.
