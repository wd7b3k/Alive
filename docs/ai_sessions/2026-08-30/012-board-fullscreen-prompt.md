## Часть 1. Доска в админке разворачивается на весь экран

Раздел «Доска» (/admin/board) показывает доску внутри `<iframe>` в
`app/src/redesign/admin-board.tsx`. Рамка ограничена шириной `.r-page` (1160px) и высотой
`calc(100vh - 260px)` — канбан из пяти колонок и список с сортировкой в неё не помещаются.

Нужна кнопка «Развернуть» / «Свернуть» над рамкой. В развёрнутом состоянии рамка занимает
всё окно: `position: fixed; inset: 0`, `z-index` выше шапки приложения, без скруглений и
внешней рамки. Кнопка живёт в компоненте раздела, не внутри iframe — там чужая страница.

Проверено заранее: у `.r-page` и `.r-admin` нет `transform`, `filter` и `perspective`,
поэтому `position: fixed` сработает и портал не нужен.

Главное ограничение: переключение не должно перемонтировать iframe. Если узел
пересоздастся, страница доски перезагрузится — слетят фильтры, выбранный вид, прокрутка и
несохранённые ручные правки, которые живут в localStorage и до выгрузки в overrides.json
существуют только в браузере. Значит: один и тот же элемент, меняется только класс.
Никаких `{expanded ? <iframe …/> : <iframe …/>}`, никакой смены `key`, никакого переноса
узла между родителями. `srcDoc` уже в `useMemo` — ссылка на строку не должна меняться
между рендерами.

Детали: Escape сворачивает; пока развёрнуто — `document.body` не прокручивается, вернуть
как было и при сворачивании, и при размонтировании; кнопка «Свернуть» видна поверх
развёрнутой рамки; `aria-pressed` и осмысленный `title`; стиль как у `.r-admin-nav`, свой
класс с префиксом `r-board-`, своих CSS-переменных не заводить; на узких экранах кнопка
тоже нужна.

Заодно, если несложно: даже в обычном виде рамка сжата до 1160px шириной `.r-page`.
Раздел «Доска» имеет смысл растянуть на всю ширину окна с полями.

`scripts/board-template.html` не трогать. Его собирает ещё и `board.mjs build`, правка в
одном месте разъедет два.

### Тесты

`@testing-library` в проекте нет — компонентные тесты идут через `renderToStaticMarkup`
(`app/src/redesign/install.test.tsx`), окружение jsdom. Новых зависимостей не добавлять.
Закрыть три вещи:

1. Узел не пересоздаётся. `react-dom/client` в jsdom: отрисовать раздел, запомнить
   `document.querySelector('iframe')`, переключить состояние, сравнить, что это тот же
   объект узла. Это главное ограничение задачи и единственное, что нельзя поймать
   глазами: сломается тихо, а заметится через неделю потерянными правками.
2. Разметка в обоих состояниях. `renderToStaticMarkup`: у рамки в развёрнутом виде свой
   класс, `aria-pressed` у кнопки меняется, `srcDoc` в обоих случаях одинаковый.
3. CSS-инвариант по образцу `app/src/redesign/css-invariants.test.ts`: правило
   развёрнутого состояния существует и содержит `position:fixed`.

## Гейты и завершение

Перед PR в `app/`: `npm run format:check`, `npm run lint`, `npm run typecheck`,
`npm test`, `npm run build` — все пять чистые, это ровно тот набор, что гоняет джоб
frontend в CI.

Руками проверить: развернуть, свернуть, фильтр и выбранный вид сохранились. Если
сбросились — iframe перемонтировался, чинить. Escape и кнопка дают одинаковый результат.

Трейлеры в тело коммита:

```
Board: done doska-v-adminke-razvorachivaetsya
Board: new tech P1 process "appliedCommit не переживает пересборку ветки" :: check видит расхождение, но не отличает забытый apply от rebase. Если записанного хеша нет среди предков HEAD — это пересборка, и сообщение должно быть другим, с готовой командой замены
Board: new tech P1 process "Трейлеры теряются, когда коммит стал предком ветки" :: после rebase коммиты уходят из диапазона appliedCommit..HEAD, и их движения не применяются никогда. Поймали случайно на PR #29 — четыре карточки остались в старых колонках
```

Затем `node scripts/board.mjs check`, `apply`, `md`, отдельный коммит
`board: применены трейлеры`, и `check` должен закончиться чисто. Проверить заодно, что
кириллица в `cards.json` не разъехалась.

Запушить ветку и открыть PR — сессия не заканчивается на локальной ветке. Мержить
merge-коммитом, не squash: в `cards.json` записан `appliedCommit`, и squash уничтожит
хеш, от которого считается диапазон. Выкладку на прод делает владелец.
