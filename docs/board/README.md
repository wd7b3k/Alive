# Доска работ

Доска не ведётся руками. Карточки лежат в репозитории, двигает их коммит,
а страница — только представление этих данных. Решение и причины —
`docs/decisions/ADR-0012-board-from-repo.md`.

## Что где лежит

| Файл | Что это |
|---|---|
| `docs/board/cards.json` | все карточки, эпики, релизы. Источник истины |
| `docs/board/overrides.json` | ручные правки, привезённые со страницы кнопкой «Правки» |
| `scripts/board.mjs` | проверка, применение трейлеров, сборка страницы, `BACKLOG.md` |
| `scripts/board-template.html` | вёрстка и код страницы. Данные в неё подставляются при сборке |
| `BACKLOG.md` | срез открытого текстом. Собирается, руками не редактируется |

## Как карточка двигается

Строкой в сообщении коммита. Одна строка — одно действие:

```
Board: done inf-users-migration
Board: doing inf-observability
Board: verify auth-live-check
Board: next perf-bundle
Board: backlog design-motion

Board: new bug P1 perf "Каталог запрашивается дважды" :: замер на старте, два дубля
Board: prio brand-logo-weight P2
Board: note inf-in-repo "ждёт доступа к серверу"
Board: doc  inf-observability docs/INFRASTRUCTURE_STATE.md
Board: chat inf-observability https://claude.ai/...
Board: drop shapka-migaet-pri-pervoy
```

`done`, `doing`, `verify`, `next`, `backlog` принимают несколько id через
пробел или запятую. `new` заводит карточку: тип и эпик — по их id из
`cards.json`, приоритет — `P0`…`P3`, заголовок обязательно в кавычках,
описание после `::`. Id новой карточки собирается из заголовка.

Каждое действие прикрепляет к карточке коммит, в котором оно записано, и
переставляет дату `updated`. Поэтому у закрытой карточки всегда есть чем
проверить, что она закрыта: ссылка на коммит, а не слово «сделано».

## Порядок в сессии

```bash
node scripts/board.mjs check    # в начале: что не применено, что расходится
… работа, коммиты с трейлерами Board: …
node scripts/board.mjs apply    # применить трейлеры к cards.json
node scripts/board.mjs md       # переписать BACKLOG.md
git add docs/board/cards.json BACKLOG.md && git commit -m "board: применены трейлеры"
```

`apply` идёт от коммита, записанного в `appliedCommit`, до `HEAD` — дважды
одно и то же не применяется. `check` падает, если трейлеры есть, а
`cards.json` их не знает, и предупреждает, если коммит трогал `app/` или
`supabase/` вообще без трейлера: значит, работа сделана, а доска о ней не
узнает. То же самое проверяет CI на каждый PR.

## Ручные правки

Правило автоматики не отменяет мышку. На странице по-прежнему можно
перетащить карточку, сменить приоритет, завести свою, написать заметку и
привязать ссылку на чат. Эти правки живут отдельным слоем и не стираются
пересборкой.

Разрешение конфликта одно и объяснимое: **правка побеждает, пока
репозиторий не сказал новее.** У каждой правки есть дата; если карточка в
`cards.json` обновлена позже, колонку и приоритет берём из репозитория, а
заметку, порядок и ссылку на чат — из правки. Так закрытая коммитом
карточка не остаётся висеть в «В работе» из-за забытого перетаскивания.

Чтобы правки не жили только в браузере, кнопка «Правки» отдаёт их файлом:
положить в `docs/board/overrides.json`, закоммитить — и они станут частью
репозитория.

## Сборка страницы

```bash
node scripts/board.mjs build            # dist/board.html
node scripts/board.mjs build /tmp/x.html
```

Собранный файл публикуется артефактом «Пульт Habitoff» на claude.ai. Адрес
артефакта постоянный: пересборка обновляет страницу по тому же адресу.
Публикацию делает сессия Claude — у скрипта доступа туда нет.

## Что доска не делает

- Не заменяет `docs/CURRENT_STATE.md`: там причины и разбор, здесь — состояние.
- Не решает, что делать. Приоритет ставит владелец, доска его показывает.
- Не знает о ветках, которые не влиты: карточка двигается коммитом в `main`.
