# Habitoff v3.0 — глубокий редизайн интерфейса

Статус: **ACTIVE / BLOCKING BEFORE FINAL v3.0**.

## Причина

Product-alpha и первый hardening сохранили функциональную глубину, но дали неприемлемую визуальную регрессию относительно 2.7:

- слабая иерархия и generic SaaS-like skin;
- недостаточно выразительный главный сценарий эпизода;
- отсутствовала цельная система иконок состояний/контекстов/действий;
- карточка эпизода не объясняла цепочку «ситуация → потребность → Замена → итог» и не мотивировала продолжать эксперимент;
- никотиновый продукт мог визуально восприниматься как «Замена», что методологически неверно;
- фирменный Habitoff/Om был ненадёжно подключён через public/CSS path;
- mobile-safe-zone и action hierarchy были недостаточными;
- в пользовательском интерфейсе осталось слишком много англоязычной технической лексики.

## Новая архитектура интерфейса

Основная навигация состоит из четырёх продуктовых разделов:

1. **Сегодня** — следующий живой выбор, главная CTA «Меня тянет», краткий пульс и история обучения;
2. **Связки** — повторяющиеся контексты и личные сценарии;
3. **Путь** — динамика относительно собственного исходного уровня и эффективность реальных Замен;
4. **Смыслы** — личные и общие опоры/identity anchors.

Методология, версии и настройки остаются вторичными и не конкурируют с главным поведенческим loop.

## Карточка эпизода — обязательная структура

Каждая карточка должна визуально и текстово разделять:

- **Ситуацию / триггер**;
- **Потребность / функцию**;
- **Что пользователь реально попробовал вместо автоматизма** — только настоящая Замена;
- **Итог** — прерванный автоматизм или конкретный никотиновый продукт/количество;
- изменение тяги и субъективную полезность при наличии данных;
- короткую неосуждающую интерпретацию, объясняющую, чему научился эксперимент.

Сигарета, кальян и электронная сигарета **никогда не называются и не оформляются как Замена**. Если Замены не было, это должно быть явно написано.

## Иконографика

Используется единая собственная SVG-система для:

- никотиновых продуктов;
- контекстов/триггеров;
- потребностей/состояний;
- Замен;
- навигации и системных действий.

Иконка должна помогать сканированию экрана, а не быть декоративным шумом.

## Логотип

Одобренный пользователем Habitoff/Om подключается как Vite-bundled asset из `app/src/assets`, а не как хрупкая абсолютная ссылка на public path. Запрещено заменять Om на `∞`, emoji или самостоятельно перерисованный знак.

## Язык интерфейса

Весь пользовательский интерфейс должен быть на русском языке, кроме:

- бренда **Habitoff**;
- собственных имён;
- официальных названий внешних сервисов/технологий, когда они действительно нужны пользователю (например Google, Supabase, PostgreSQL).

В пользовательском тексте запрещены без необходимости:

- `baseline` → **исходный уровень**;
- `check-in` → **итоги дня / вечерний разбор**;
- `units` → **единицы Habitoff**;
- `review` → **проверка / рассмотрение**;
- `raw` → **исходные факты / события**;
- `NRT` → **никотин-заместительная терапия / НЗТ**;
- `frontend` → **интерфейс**.

Внутренние имена полей, API и кодовые значения могут оставаться английскими, поскольку пользователь их не видит.

## Mobile-first gate

- `safe-area-inset-*` учитывается во всех fixed/sticky областях;
- главный CTA не конкурирует с навигацией;
- mobile bottom navigation содержит только четыре главных раздела;
- минимум 44×44 px для иконок-кнопок и 48 px для основных действий;
- независимые действия не касаются друг друга и системных краёв;
- длинный эпизодный flow помещается в `100dvh` и скроллится внутри безопасного контейнера.

## Release gate

Редизайн нельзя сливать в production только потому, что TypeScript/build зелёные. Перед merge необходим реальный визуальный smoke-test минимум на мобильном 390–430 px и desktop 1280+ px, включая:

- логотип;
- Сегодня;
- все четыре шага эпизода;
- карточку успешного эпизода;
- карточку эпизода с никотином и без Замены;
- Связки;
- Путь;
- Смыслы;
- профиль и вечерний разбор.
