## Что сделать

1. Миграция `content_translations` по §2 разбора: `entity`, `row_key`, `field`, `locale`,
   `value`, `source_hash`, `status`, `updated_at`; первичный ключ по первым четырём;
   RLS: чтение `anon` только при `status = 'published'`, запись — только через миграции.
2. Функция `public.content_hash(text)` — `sha256` нормализованного исходника, чтобы хэш
   считался одинаково в миграции, в тесте и в админке.
3. Витрины `*_localized(locale)` (или одна RPC `public.catalog(locale)`) для девяти
   каталогов: возвращают переведённое поле при `status='published'` и совпавшем хэше,
   иначе русский оригинал.
4. `app/src/data.ts` и `hooks/usePublicCatalog.ts`: локаль — параметр загрузки, второй
   ветки кода не заводится.
5. Гарды: SQL-тест «нет опубликованного перевода с разошедшимся хэшем», SQL-тест
   «в EN-значениях нет кириллицы», расширение `rls-migrations.test.ts`.
6. Витрина расхождений в админке: сколько карточек переведено, сколько отстало от
   русского исходника, по каким таблицам. Разделу хватает таблицы — украшать нечего.
7. Документы: `docs/DATA_MODEL.md`, `docs/ADMIN.md`, `docs/ARCHITECTURE.md`, навигатор.
