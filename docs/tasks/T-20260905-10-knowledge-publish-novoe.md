## Свести движок статей с принятым решением main (делается до всего остального)

Разбор верен: посылка моего движка — «текста утверждения в репозитории не существует» —
отменена принятым и выложенным решением `ADR-0017` про выгрузку каталога. Спорить с
выложенным решением нечем, и разводить два способа читать каталог тоже нельзя.

**Решение: подстановка `{{claim:<код>}}` берёт текст из `app/knowledge-catalog.json`.**

Что из этого следует, по пунктам:

- `content/knowledge/claims.lock.json` и `scripts/knowledge-lock.mjs` **удаляются**. Замок
  из кодов и хэшей существовал ровно затем, чтобы проверка работала там, где нет базы.
  Выгрузка закоммичена — значит текст доступен и в CI, и на сервере, и второй механизм
  становится лишней сущностью. Расхождение с базой ловит `dump-knowledge-catalog.mjs --check`,
  который для этого и написан;
- сборка **не ходит в базу**. Ни через `psql`, ни через PostgREST. Один источник на сборке —
  закоммиченная выгрузка. Это заодно закрывает карточку `katalog-na-sborke-chitayut`:
  расхождения двух способов чтения больше нет, потому что способ один;
- ссылка на несуществующий или неопубликованный код роняет сборку — как и раньше, только
  проверка идёт по выгрузке, а не по замку;
- пространство имён: карточки `/knowledge/<код>` плоско, статьи `/knowledge/<кластер>/<слаг>`
  вложенно. `codeFromPath` возвращает `null` для вложенного пути, так что они не конфликтуют.
  Единственный нужный гард — слаг кластера не равен ни одному коду карточки;
- `ADR-0018` (свободный номер — верно) пишется заново, а не переименовывается: его предмет
  теперь «статьи базы знаний: собственный текст в репозитории, утверждения каталога —
  подстановкой из выгрузки». Старую формулировку про отсутствие копии не переносить, она
  противоречит `ADR-0017`;
- по четырнадцати пересекающимся файлам ведущей считается версия `main`. Из ветки
  `task/knowledge-base` берётся только то, чего в `main` нет: слой статей, шаблоны,
  редакционные гарды, `EDITORIAL_PROTOCOL_MED.md`.

Если при сведении обнаружится, что чего-то из этого сделать нельзя, — остановиться и
сказать, а не выбирать вариант самостоятельно.

## Как статьи входят в общую логику сервиса (дополнение 05.09, по вопросу владельца)

Проверено по коду: сейчас **не входят никак**. Тип `Article` в ветке несёт `slug`, `cluster`,
`question`, `answer_short`, `level`, `claims`, `sources`, `related`, `faq` — и ни одного поля,
по которому движок мог бы решить, где показать разбор. Единственная связь в приложении —
ссылки на разборы под карточками внутри самого раздела `/knowledge`
(`app/src/redesign/knowledge.tsx`). В потоке тяги, «Связках», «Сегодня» и на экране до входа
статей нет вовсе. Граф связей `knowledge-related.ts` на `main` считает близость **только между
карточками**, статьи в нём не участвуют.

Это закрывается здесь же, иначе каждую неделю будет прибавляться контент, живущий отдельно от
продукта.

### 1. Главный механизм — обратный индекс из цитат

Статья уже цитирует карточки через `{{claim:<код>}}`. На сборке строится обратный индекс
**«код карточки → статьи, которые её цитируют»**. Из него бесплатно получается:

- на странице карточки `/knowledge/<код>` — блок «Подробнее» со ссылками на разборы;
- в приложении: там, где карточка уже показывается, под ней та же ссылка. Карточки разложены
  по `surfaces`, `trigger_codes`, `need_codes`, `product_types` — **статья наследует контекст
  цитируемой карточки и не требует собственной разметки.**

Это правильная зависимость: контекст живёт в каталоге, который редактируется миграциями, и не
дублируется во фронтматтере каждой статьи.

### 2. Собственные поля — только там, где карточки нет

Часть разборов не цитирует ни одной карточки по своей теме (закон, доклад ВОЗ). Для них у
статьи есть собственные поля — **они уже проставлены во всех восьми файлах**:

```yaml
triggers: []            # коды пусковых моментов каталога
needs: []               # коды потребностей
product_types: []       # cigarette | hookah | vape
tags: []                # словарь context_tags каталога
surfaces: []            # links | today | public
```

Значения — из тех же справочников, что у карточек. Неизвестный код роняет сборку: иначе словари
разъедутся, и выяснится это на экране пользователя.

### 3. Чего у статьи не бывает: `flow`

Поверхности `flow` у статьи нет и быть не может. Принцип `P17` — минимум действий в момент тяги;
ссылка на разбор в этот момент уводит человека из сценария ровно тогда, когда он пришёл за
помощью, а не за чтением. Гард: `surfaces` статьи с `flow` роняет сборку.

### 4. Фильтр по продукту

Тот же, что у карточек (`appliesToProducts` в `app/src/domain/knowledge.ts`): тому, кто парит, не
показывается кальянный материал. Пустой `product_types` — «подходит всем».

### 5. Связи двусторонние и ограниченные

Как в `knowledge-related.ts`: если карточка ведёт на статью, статья ведёт на карточку. Под одной
карточкой — не больше двух-трёх ссылок на разборы, иначе подвал перестаёт быть подсказкой.
Порядок детерминирован, чтобы сборка не переписывала страницы без причины.

### 6. Индекс для приложения

Приложение не читает markdown. Сборка кладёт `app/knowledge-articles.json` — лёгкий индекс
(слаг, кластер, заголовок, вопрос, уровень, `claims`, `triggers`, `needs`, `product_types`,
`tags`, `surfaces`) и коммитит его тем же принципом, что и выгрузку каталога: изменение контента
видно в диффе и проходит ревью.

### 7. Событие перехода

Переход «карточка → разбор» отмечать `trackEvent` с кодом карточки и слагом статьи. Без этого
через месяц нельзя будет ответить, работает связь или просто занимает место.

## Приёмка — команды и ожидаемый вывод

- `curl -sI https://habitoff.ru/knowledge/novoe/<слаг>` — 200 по каждому из восьми;
- `curl -s https://habitoff.ru/knowledge/novoe/<слаг> | grep -o '<title>[^<]*'` — восемь
  разных заголовков;
- `curl -s https://habitoff.ru/sitemap.xml | grep -c '<loc>'` — прежнее число плюс девять;
- `node scripts/check-deploy-drift.mjs` — сборка совпадает с `origin/main`;
- `curl -sI https://habitoff.ru/knowledge/novoe/<слаг> | grep -i x-robots-tag` — пусто;
- `curl -s https://habitoff.ru/knowledge/<любой код карточки> | grep -o '<title>[^<]*'` —
  не изменился;
- обратный индекс работает: на странице карточки, которую цитирует разбор, есть ссылка на него,
  и обратно; на карточке без цитат блока «Подробнее» нет;
- негативные проверки: статья с `surfaces: [flow]` роняет сборку; неизвестный код триггера,
  потребности, продукта или тега роняет сборку;
- `app/knowledge-articles.json` собран и содержит восемь записей;
- скриншот или вывод из Вебмастера и Search Console о принятых заявках на переобход.

## Не делать

- не переписывать статьи заново; правки по существу — только при найденной фактической
