## Что расширяем

Расширяются три существующих механизма, новых сущностей не заводится:

- `scripts/state.sh` — уже собирает состояние; добавляются четыре проверки;
- `.github/workflows/frontend-ci.yml` — уже содержит джобы `board` и предупреждение о
  `CURRENT_STATE.md`; добавляются два джоба;
- `scripts/next-adr.sh` — уже выдаёт номер ADR; по его образцу делается `next-id.sh` для
  постановок и записей сессий.

Почему существующего не хватает: в `AGENTS.md` шестнадцать правил, у одиннадцати есть
команда, у пяти её нет. Именно эти пять нарушены прямо сейчас — цифры в разборе
`R-20260906-01`.

## Стоп-условие

Остановиться и спросить, если:

- джоб «пределы» на текущем состоянии `main` роняет сборку сразу (`doing` = 8, приоритет 0
  у 44 карточек, в очереди 14 постановок). Тогда решается, чинить состояние до включения

- `check-numbers.mjs` находит больше двадцати чисел-фактов в документах: тогда чинить их
  надо отдельной задачей, а не этой.

## Инварианты — нарушать нельзя

- правило без проверки не считается требованием к сессии (`AGENTS.md`, шапка);
- число, которое проверяет машина, в документ не копируется (`AGENTS.md`, инвариант
  «Evidence-first» в редакции 06.09);
- одна задача — одна ветка — одна карточка (`AGENTS.md`, «Постановка»);
- проверка обязана уметь провалиться (`AGENTS.md`, инвариант 5): для каждого нового
  джоба и скрипта показать, что он падает на подложенном нарушении;
- навигатор обновляется той же задачей (`AGENTS.md`, «Порядок загрузки контекста»).

## Что сделать

1. **`scripts/next-id.sh`** — по образцу `next-adr.sh`. Аргумент: `R`, `T` или `session`.
   Для `R` и `T` сканирует `docs/tasks/`, для `session` — `docs/ai_sessions/<сегодня>/`,
   возвращает следующий свободный номер за текущую дату. Учитывает, что `R` и `T`
   нумеруются независимо.
2. **Джоб CI «постановка»** — падает, если в `docs/tasks/` или в одном дне
   `docs/ai_sessions/` есть два файла с одинаковым номером; падает, если тема в имени
   файла `T-`/`R-` не входит в список `epic` из `cards.json`.
   На текущем `main` он обязан упасть: три коллизии в `docs/tasks/` (`R-20260905-01`,
   `T-20260905-11`, `T-20260905-12`) и две в `docs/ai_sessions/2026-09-05/` (004, 005).
   Коллизии развести переименованием файлов со сдвигом номера, ссылки на них в документах
   и коде поправить тем же коммитом.
3. **Эпики доски** — добавить в `cards.json` недостающие: `knowledge`, `i18n`, `legal`,
   `money`, `social`, `data`. Без них задачи двенадцати существующих постановок не могут
   закрыться карточкой, а джоб из пункта 2 будет падать на верных темах.
4. **Джоб CI «пределы»** — считает по `cards.json` и `docs/tasks/`: `doing` не больше двух,
   карточек с приоритетом 0 не больше трёх, неисполненных `T-` не больше одной. Режим —
   по решению из «Стоп-условия».
5. **`scripts/check-numbers.mjs`** — ищет в `CLAUDE.md` и `docs/*.md` числа, которые
   проверяет машина: «N карточек», «N документов», «N миграций», «N таблиц», «N тестов»,
   «N веток». Падает со списком мест. Известные на 06.09: `CLAUDE.md` — «150 карточек»
   при 214.
6. **`scripts/state.sh`** — четыре добавления:
   - первой строкой вывода: отставание локального `main` от `origin/main` после `git fetch`;
     отставание больше нуля — вывод начинается со стоп-строки;
   - untracked `.md` в `docs/` и `docs/tasks/` — отдельный раздел «постановка вне git»;
   - вызов `node scripts/check-numbers.mjs`;
   - вызов джоба пределов в локальном режиме.
7. **Проверка экрана в браузере** — `scripts/check-screen.mjs`: открывает переданный адрес
   в headless-браузере, ждёт монтирования и печатает видимый текст и код ответа. Нужна для
   роли `priyomka`: 05.09 `curl` отвечал 200 на девятнадцати страницах, невидимых для людей.
   Playwright или puppeteer — на выбор исполнителя, но браузер ставится один раз и в
   репозиторий не коммитится.
8. **`board.mjs check`** — предупреждение, если карточка ушла в `done`, а её `chats` пуст
   или все ссылки в нём пустые. На 06.09 непустая ссылка есть у 2 карточек из 214.
9. **Навигатор** — строки о новых скриптах и джобах в том же коммите.
10. **`AGENTS.md`** — в таблице «правило → проверка» снять значок ⚠ с тех строк, чьи
    проверки заработали. Значок остаётся только там, где проверки по-прежнему нет.

## Приёмка — команды и ожидаемый вывод

- `bash scripts/next-id.sh T` — печатает следующий свободный номер за сегодня;
- подложить дубль постановки и прогнать джоб «постановка» локально — падает; убрать —
  проходит;
- `node scripts/check-numbers.mjs` — на исправленном `CLAUDE.md` проходит; после возврата
  строки «150 карточек» падает;
- `bash scripts/state.sh` на копии с искусственно отставшим `main` — первой строкой стоп;
- `node scripts/check-screen.mjs https://habitoff.ru/knowledge` — печатает видимый текст
  страницы, а не пустой контейнер;
- `node scripts/board.mjs check` — предупреждение о карточках без чата присутствует;
- `npm run lint && npm run typecheck && npm test && npm run build` — зелёные;
- PR открыт, CI зелёный на нём целиком.

## Не делать

- не чинить в этой задаче сами нарушения пределов (44 карточки с приоритетом 0, восемь
  `doing`, очередь постановок) — это отдельная работа роли `sostoyanie`;
- не переписывать содержимое документов, найденное `check-numbers.mjs`, кроме `CLAUDE.md`;
- не трогать `app/src/**` сверх того, что нужно скрипту проверки экрана;
- найденное попутно — `Board: new` в том же коммите.
