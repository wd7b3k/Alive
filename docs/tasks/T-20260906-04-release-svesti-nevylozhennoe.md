## Стоп-условие

Остановиться и спросить, если:

- ветка при слиянии откатывает состояние назад — то есть её содержимое старше того, что
  уже в `main`. 05.09 две ветки выглядели «впереди» и содержали более старую редакцию;
- в ветке лежит миграция с датой раньше последней применённой в базе. Применятель
  отбирает файлы по отсутствию записи в журнале, а не по дате, и применит её к более
  новой схеме, чем та, против которой она написана;
- содержимое `content/knowledge/novoe/` расходится с тем, что уже опубликовано в каталоге:
  тогда это работа роли `znaniya`, а не выкладка.

`RUNBOOK_KNOWLEDGE_WEEKLY.md` — постоянная процедура еженедельного выпуска, на которую
ссылается задача по расписанию в понедельник 09:00. Пока файла нет в `origin`, свежая
сессия понедельника его не найдёт. Довести до `origin` в первую очередь, отдельным
коммитом, до всего остального.

Восемь разборов в `content/knowledge/novoe/` — проверить у роли `znaniya`, опубликованы
ли соответствующие карточки каталога. Опубликованные — слить; неопубликованные — слить как
черновики с `published = false`, не выкладывая.

## Приёмка — команды и ожидаемый вывод

- `git status --porcelain` в рабочей копии владельца — untracked-файлов из пункта 1 нет;
- `for b in ...; do git rev-list --count origin/main..$b; done` — по каждой из восьми
  веток либо 0, либо записанное решение «закрыть/подвесить» в файле результата;
- `node scripts/check-deploy-drift.mjs` — расхождения нет;
- `curl -s https://habitoff.ru/version.json` — коммит совпадает с `origin/main`;
- открыть в браузере `/knowledge` и любой новый адрес карточки — содержимое видно человеку,
  а не только краулеру;
- `node scripts/board.mjs check` — зелено, трейлеры применены.

## Не делать

- не удалять ветки без решения владельца;
- не сливать миграции задним числом до проверки применятеля;
- не публиковать карточки каталога, решение о публикации которых не принято, — это работа
  роли `znaniya`, а не выкладки;
- не чинить найденное по дороге: `Board: new` в том же коммите.
