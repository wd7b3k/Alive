# Способы входа

На 24.08.2026 работает один: Google. Ниже — что нужно, чтобы добавить российские.

Интерфейс к этому готов: список кнопок берётся из переменной `VITE_AUTH_PROVIDERS`
(через запятую, первый в списке — главная кнопка). По умолчанию `google`. Кнопка
появляется только для провайдера, который уже заведён в Supabase: иначе человек нажал
бы и получил ошибку на весь экран.

## Яндекс — делается сейчас

Supabase поддерживает произвольные OAuth2-провайдеры; на бесплатном тарифе их можно
завести до трёх. У Яндекса нет OIDC-discovery, поэтому нужен режим **OAuth2** с
адресами, вписанными вручную.

| Поле | Значение |
| --- | --- |
| Authorization endpoint | `https://oauth.yandex.ru/authorize` |
| Token endpoint | `https://oauth.yandex.ru/token` |
| User info endpoint | `https://login.yandex.ru/info?format=json` |
| Идентификатор в Supabase | `custom:yandex` |

Порядок:

1. На `oauth.yandex.ru` создать приложение, выдать ему права «Доступ к адресу
   электронной почты», «Доступ к портрету пользователя», «Доступ к логину, имени и
   фамилии, полу».
2. В Supabase → Authentication → Providers добавить custom-провайдера с именем
   `yandex`, вписать Client ID и Client Secret приложения и адреса из таблицы.
3. Скопировать из Supabase read-only callback URL и вписать его в приложение Яндекса
   как Redirect URI.
4. В Cloudflare Pages задать `VITE_AUTH_PROVIDERS=google,custom:yandex` и пересобрать.

**Что нужно проверить на первом же живом входе**, а не считать заранее верным: Яндекс
документирует заголовок `Authorization: OAuth <token>` для `login.yandex.ru/info`, тогда
как обобщённый OAuth2-клиент отправляет `Bearer`. Если Яндекс ответит 401, вход
сломается ровно на шаге получения профиля — и лечится это не в приложении, а прослойкой
(см. ниже) или сменой режима провайдера.

Секреты приложения ввожу не я: их вводит владелец в своей панели.

## VK ID и Mail.ru — отдельная работа, не настройка

VK ID (и Mail.ru, который в него переведён) работает по OAuth 2.1: PKCE обязателен, а
при обмене кода на токен требуется дополнительный параметр `device_id`. Обобщённый
OAuth2-клиент Supabase этого не умеет, поэтому «добавить провайдера в панели» здесь не
сработает.

Рабочий путь — прослойка: Edge Function, которая проводит обмен по правилам VK ID и
затем выдаёт сессию Supabase. Это не настройка, а код, который держит в руках
пользовательские токены, и делать его надо отдельным release unit с собственными
проверками.

Пока этого нет, честнее не показывать кнопку VK, чем показывать неработающую.

## Проверка перед тем, как объявлять способ входа рабочим

1. Вход в приватном окне с аккаунта, которого ещё нет в базе.
2. `profiles` получил строку: `display_name` не пустой, `role` = `participant`.
3. `user_settings` создан.
4. Повторный вход тем же аккаунтом не создаёт второй профиль.
5. Выход и вход другим способом с той же почтой — проверить, склеились ли аккаунты
   или получились два. Это поведение зависит от настройки Supabase, и его надо
   увидеть, а не предположить.
