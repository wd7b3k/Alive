# Коррекции процесса разработки ALIVE

Этот файл хранит процессные решения, которые сознательно исправляют более ранние правила. История предыдущих решений не удаляется.

## 2026-08-17 — отказ от обязательного local checkout

### Было

После первого неудачного запуска Codex было введено жёсткое правило: при отсутствии локального git checkout задача должна останавливаться с `BLOCKED: LOCAL_REPOSITORY_UNAVAILABLE`.

### Что выяснилось

Правило хорошо ловило пустой sandbox, но было плохо согласовано с реальным способом управления ALIVE.

Владелец проекта развивает продукт через агентов, канонические документы, отдельные ветки и PR и не должен вручную становиться программистом или DevOps для запуска каждого release.

### Новое решение

Основным owner workflow становится **Direct GitHub Mode**.

Если `wd7b3k/Alive` доступен через подключённый GitHub на чтение и запись, Codex продолжает работу без локального checkout.

Безопасность обеспечивается:

- отдельной branch;
- небольшими commits;
- draft PR;
- GitHub Actions;
- Supabase development tooling;
- preview/browser QA;
- validation state;
- rollback/forward-fix;
- owner merge gate.

Local Repository Mode сохраняется как удобный дополнительный режим, но не как требование владельцу.

### Главный вывод

> **Quality gates должны уменьшать ошибки агента, а не увеличивать техническую нагрузку на владельца продукта.**
