# Рантбук: еженедельный выпуск базы знаний

Постоянная процедура. Выполняется раз в неделю, по понедельникам. Заведена 05.09.2026,
после того как первый выпуск из восьми разборов был написан вручную.

**Результат недели — один-три новых разбора на сайте, а не отчёт о проделанной работе.**
Если неделя прошла и читателю нечего открыть — неделя не удалась, сколько бы источников ни
было просмотрено.

Кто выполняет: сессия по расписанию (сбор, отбор, написание) и Claude Code на машине
владельца (мерж, выкладка, индексация). Владелец — только там, где без него физически
нельзя: переобход в Вебмастере и Search Console.

## 1. Сбор — что вышло за неделю

Окно: с даты `last_run` из `state.json` по сегодня. Для первого выпуска после перерыва
окно расширяется до фактического пробела.

Источники, все с открытым доступом:

- **PubMed E-utilities** — `esearch` с `datetype=edat`, `mindate`/`maxdate`, затем
  `esummary`. Набор запросов — в `content/knowledge/harvest/queries.json`;
- **Кокрейновская библиотека** — новые и обновлённые обзоры по табаку и никотину. Живые
  обзоры переиздаются часто, и версия имеет значение;
- **ClinicalTrials.gov** (API v2) — результаты и смена статуса по ключевым вмешательствам;
- **FDA** (в том числе центр табачной продукции), **EMA**, **ВОЗ**, **NICE** —
  регуляторные решения, руководства, доклады;
- оглавления **Tobacco Control**, **Addiction**, **Nicotine & Tobacco Research**;
- **medRxiv** — отдельной корзиной, см. фильтр;
- российский контур: **Минздрав**, **Роспотребнадзор**, **Росстат**, изменения 15-ФЗ,
  обзоры законодательства.

**Недоступный источник и пустой улов — разные вещи.** Если источник не ответил, это
записывается и говорится вслух: «ничего нового» и «мы не знаем» путать нельзя.

## 2. Отбор — о чём писать

В работу проходит: систематический обзор, метаанализ, РКИ, клиническое руководство,
регуляторное решение, доклад международной организации, изменение закона, крупная когорта.

Не проходит: препринт (только в очередь, с пометкой); одно небольшое наблюдательное
исследование; новость без первоисточника; «ещё одно исследование подтвердило известное».

**Приоритет — по разрыву с русскоязычной выдачей.** Чем громче тема в мире и тише
по-русски, тем выше. Проверяется поиском, а не ощущением: если по теме уже есть внятные
русские материалы с источниками, ценность разбора ниже.

Норма недели — **один-три разбора**. Больше — значит отбор не сработал; лишнее уходит в
`queue.md` темой, а не ссылкой.

## 3. Куда пишется — обновление или новый адрес

Порядок проверки, именно в этом порядке:

1. **Тема уже есть в базе знаний** → обновляется существующая статья: новый источник,
   правка вывода, строка в `changelog`, `updated` двигается. Нового адреса не создаётся.
   Это **предпочтительный исход**: статья, которая живёт третий год и трижды обновлялась,
   сильнее трёх новых;
2. **Темы нет** → новая статья в `content/knowledge/novoe/`, слаг по теме, а не по дате:
   `elektronnye-sigarety-i-otkaz-ot-kureniya`, а не `obzor-kokrejn-sentyabr-2026`. Через
   год та же тема обновится на том же адресе;
3. **Тема — утверждение, которое продукт уже сделал от своего имени** → это правка карточки
   каталога, а не статья. См. §7.

Страницы «выпуск за неделю N» не заводятся никогда: пятьдесят две тонкие страницы в год в
медицинской теме не ранжируются и портят впечатление о разделе целиком.

## 4. Как пишется разбор

Форма — общий инвариант базы знаний:

> ответ в 2–3 предложениях → уровень и на чём основан → что известно → **чего не знают** →
> что это меняет для тебя → источники с датами → журнал изменений

Обязательное для разбора:

- **первоисточник, а не пресс-релиз.** Не дотянулись до публикации — тема уходит в очередь;
- в начале — что вышло, где и когда;
- отдельно — **чего эта работа не показала.** У свежих публикаций это половина ценности и
  единственное, чем разбор отличается от новости;
- 700–1200 слов собственного текста;
- ссылки вглубь: цитаты каталога `{{claim:<код>}}` и связанные статьи;
- изложение чужой работы с атрибуцией — «обзор показал», а не «доказано». Утверждение от
  имени продукта — это карточка, и она идёт через владельца.

Запрещено (проверяется тестом `EDITORIAL_PROTOCOL_MED`): дозировки, рекомендации
препаратов, сравнения «что лучше», медицинские обещания, изображения продукции, три
утверждения из `llms.txt` («тяга 3–5 минут», «вейп на 95 % безопаснее», «кальян = N сигарет»).

**Слаг статьи не совпадает ни с одним кодом карточки и ни с одним слагом кластера** —
`/knowledge/<код>` и `/knowledge/<кластер>` живут в одном пространстве имён.

**Контекстные поля обязательны — статья должна попадать в разделы приложения, а не лежать
отдельно.** Во фронтматтере: `triggers`, `needs`, `product_types`, `tags`, `surfaces`.
Значения — из тех же справочников, что у карточек; неизвестный код роняет сборку.

Главный способ привязки — цитата: статья, цитирующая `{{claim:<код>}}`, автоматически
появляется ссылкой там, где показывается эта карточка, — контекст наследуется от неё.
Собственные поля нужны там, где подходящей карточки нет (закон, статистика).

**`surfaces` статьи никогда не содержит `flow`.** Принцип `P17`: в момент тяги человеку
нужно меньше действий, а не ссылка на лонгрид. Гард роняет сборку.

## 5. Реестр и состояние

- статья добавляется в `content/knowledge/clusters.json` в список кластера `novoe`,
  редакционным порядком: выше то, что отвечает на вопрос человека о себе, ниже —
  регулирование и статистика;
- `state.json`: обновить `last_run`, добавить разобранное в `covered`, отклонённое — в
  `rejected` **с причиной**;
- `queue.md`: снять взятое, добавить новое отложенное.

## 6. Проверки перед выкладкой

```
node scripts/knowledge-lock.mjs --check
node scripts/dump-knowledge-catalog.mjs --check
node scripts/check-knowledge-links.mjs
npm --prefix app run test
npm --prefix app run typecheck
npm --prefix app run lint
node scripts/board.mjs check
```

Латиница: в телах статей допустимы только адреса в сносках, коды `{{claim:...}}` и имена
собственные из allowlist. Гард роняет сборку — расширить allowlist точечно, **не отключать**.

## 7. Карточки каталога — только по необходимости

Если находка меняет утверждение, которое продукт уже сделал:

- миграция `supabase/migrations/<метка>_v3_knowledge_weekly_<ГГГГ-НН>.sql`, вставки
  идемпотентные, **новая карточка `published = false`**;
- `code` карточки — это её вечный публичный адрес `/knowledge/<код с дефисами>`: только
  `[a-z0-9_]`, **без дефисов**, осмысленный, никогда не переименовывается;
- `source_id` обязателен: выгрузка соединяет карточку с библиографией внутренним
  соединением, и карточка без источника не имеет страницы вовсе;
- после применения — `dump-knowledge-catalog.mjs` и `knowledge-lock.mjs`, коммит вместе с
  миграцией;
- публикация карточки — **решение владельца**, не прогона.

**Ноль карточек за неделю — нормальный результат.**

## 8. Выкладка и индексация

По `docs/RELEASE_POLICY.md`: PR → мерж в `main` → `/srv/alive/deploy.sh` →
`node scripts/check-deploy-drift.mjs`.

Проверка живого прода по каждому новому адресу: код 200, свой `<title>`, `canonical` на
себя, текст в HTML без выполнения JavaScript, разметка не описывает отсутствующего,
`X-Robots-Tag: noindex` на публичных адресах нет, прежние адреса не изменились.

Индексация:

- **IndexNow** — пинг об изменённых адресах из скрипта выкладки после переключения симлинка;
- **Яндекс.Вебмастер** (владелец): переобход новых адресов; «Оригинальные тексты» —
  загрузить **до** любой публикации фрагментов в Дзене и соцсетях;
- **Search Console** (владелец): запрос индексирования, переотправка карты сайта;
- `llms.txt` и RSS обновляются сборкой, числа берутся из базы.

## 8а. Куда сессия кладёт файлы

Сессия по расписанию пишет файлы в **основную рабочую копию**
`C:\Users\ПК\Projects\alive\Alive`, как untracked: `git status` показывает их в основной
копии и **не показывает в воркtree** — воркtree делит с ней только `.git`, но не рабочий
каталог. Untracked-файл не лежит ни в одной ветке, поэтому его не найдут ни `git grep`, ни
обход веток.

Поэтому Claude Code первым делом копирует новое из основной копии в свой воркtree и
коммитит. Пока файл не закоммичен, для всех остальных сессий его не существует. Эта строка
здесь потому, что 05.09.2026 из-за этого час искали восемь готовых статей.

## 9. Оформление

`docs/ai_sessions/<дата>/NNN-*`, PR. Пуш из облачной сессии невозможен — ветку и PR
доводит Claude Code на машине владельца.
