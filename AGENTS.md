# Правила работы AI с Habitoff

Считать корень репозитория `wd7b3k/Alive` корнем самостоятельного продукта Habitoff.
Имя репозитория историческое — продукт до августа 2026 назывался ALIVE.

## REPO = единственный source of truth

Репозиторий `wd7b3k/Alive` является **единственным каноническим источником истины**.

Обязательные следствия:

- решение, которого нет в git, не считается принятым состоянием проекта;
- чат, память AI, локальный файл, ZIP, панель провайдера, SSH-сессия на сервере — не
  являются самостоятельным source of truth;
- внешняя конфигурация, влияющая на работу продукта, должна иметь безопасное
  версионируемое отражение в `docs/` или config-файлах репозитория без секретов;
- схема БД и содержимое каталогов меняются только versioned migrations из репозитория;
- код edge-функций живёт в `supabase/functions/` и на сервер синхронизируется, а не
  правится там;
- production deployment должен быть связан с конкретным commit;
- рабочие копии AI создаются только как временные каталоги и удаляются после публикации;
- результат разработки передаётся через GitHub branch/PR/release, а не через отдельный
  склад файлов на компьютере владельца;
- каждый следующий AI/разработчик сначала восстанавливает состояние из репозитория и
  только затем использует чат как дополнительный контекст;
- при расхождении между чатом и репозиторием каноническим считается репозиторий, пока
  владелец явно не утвердит изменение и оно не будет записано в git.

Исторический источник до отделения продукта: `wd7b3k/humanos/projectsv2.0/products/alive/`.
После завершения миграции он считается архивным и неканоническим.

## Своя инфраструктура: что это меняет для AI

С 27.08.2026 продукт работает на собственном сервере, а не на Cloudflare Pages и
Supabase Cloud. Панели, через которую можно было руками поменять прод, больше нет — но
её место не должен занять `psql` по SSH.

- **Прямой `psql` на боевой базе — только чтение.** Любое изменение схемы или контента —
  миграция в репозитории.
- Проверка встроена в выкладку: число файлов миграций обязано равняться числу записей в
  `supabase_migrations.schema_migrations`. Расхождение ловит машина, а не глаза.
- Выкладка невозможна из грязного рабочего дерева git. Это физический запрет выложить то,
  чего нет в коммите.
- Секреты живут в `.env` на сервере с правами `600`. В git — никогда, включая `app/.env`.
- Порядок выкладки, отката и применения миграций описан в `docs/RELEASE_POLICY.md` —
  здесь он намеренно не дублируется, чтобы два описания не разошлись.

## Статус проекта

Habitoff является некоммерческим экспериментальным проектом, возникшим из личной
потребности автора справиться с никотиновой зависимостью.

До отдельного решения владельца запрещено:

- оптимизировать продукт под выручку;
- добавлять рекламу;
- строить рекламные профили;
- продавать или передавать sensitive data для коммерческого таргетинга;
- делать monetization requirement частью архитектуры.

Изменение некоммерческого статуса требует явного обновления `PROJECT_CHARTER.md` и
отдельного ADR.

## Авторство и заимствования

Habitoff — авторская система в смысле композиции, продуктовой логики и конкретной
реализации, но не заявляет исключительного происхождения всех идей.

AI обязан:

- отделять оригинальные продуктовые решения от общеизвестных/заимствованных методик;
- не выдавать широко известные психологические, медицинские или behavioural техники за
  изобретение проекта;
- добавлять источники и атрибуцию, когда конкретное заимствование идентифицировано;
- не копировать защищённые тексты/протоколы без проверки допустимости использования.

## Evidence-first

Факты, гипотезы и эвристики всегда разделяются.

Каждое медицинское или научное утверждение, способное повлиять на здоровье пользователя,
должно иметь проверяемое основание. Для актуальных медицинских вопросов использовать
свежие авторитетные источники.

Рабочие эвристики проекта должны называться эвристиками.

Примеры:

- `1 кальян = 10 единиц` — behavioural heuristic, не эквивалент вреда;
- `10 затяжек вейпа = 1 единица` — behavioural heuristic, не эквивалент никотина или вреда.

## Никаких медицинских обещаний

Запрещено обещать, что продукт:

- вылечит зависимость;
- гарантированно поможет бросить;
- заменяет врача/психотерапевта/доказательную фармакотерапию;
- гарантирует увеличение продолжительности жизни.

Допустимо объяснять потенциальную пользу отказа от курения как общий медицинский факт при
корректной атрибуции.

## UX: nothing unexplained

Любая специфическая сущность, метрика или термин должны быть понятны человеку без
знакомства с проектом.

Для каждой неочевидной сущности предусматривать:

- понятное название;
- короткое объяснение на месте;
- `Подробнее`/tooltip для глубины;
- осмысленное empty state.

Нельзя полагаться на то, что пользователь знает внутреннюю терминологию разработчиков.

## Privacy-by-design

- private by default;
- data minimization;
- чувствительный текст не попадает в общую аналитику;
- пользовательские Смыслы/Связки не публикуются автоматически;
- UGC попадает в admin review только после явного `Предложить в общую базу`;
- группа `Вместе` работает только на разрешённых агрегатах;
- service secrets никогда не попадают во frontend/git/logs;
- реальные чувствительные данные и токены в git запрещены;
- счётчики стоят на всех страницах, включая личные (ADR-0015, решение владельца
  28.08.2026); вебвизор выключен в коде явно, тексты записей и идентификаторы записей
  в счётчики не уходят никогда.

## Архитектурная дисциплина

- не строить инфраструктуру «на будущее» без gate;
- предпочитать простую модульную архитектуру;
- границы модулей и ownership должны быть явными;
- private module data нельзя менять из другого модуля в обход его публичного API/port;
- schema/data semantics versioned;
- raw behavioural events сохраняются отдельно от пересчитываемых моделей/эвристик;
- изменения unit models не должны переписывать raw history;
- **никаких внешних сервисов в рантайме прода, кроме перечисленных явно.** Разрешены:
  Let's Encrypt за сертификатом, провайдеры входа при нажатии кнопки, счётчики Метрики и
  GA (ADR-0015). Всё остальное — CDN, шрифты, облачные функции — по-прежнему требует
  решения владельца, а не появляется деталью реализации. Служебный обмен между своими
  серверами (пульс мониторинга, ADR-0013) под инвариант не подпадает: он не участвует в
  обслуживании посетителя.

## LLM

LLM может помогать с объяснениями, классификацией UGC и разработкой, но:

- не является source of truth для статистики;
- не имеет прямого privileged доступа к БД;
- не принимает security/privacy решения;
- не назначает медицинскую дозировку;
- не публикует UGC автоматически.

## Релизы

- v2.7 — legacy reference/rollback;
- v2.8 не является production release;
- новая каноническая линия начинается с v3.0;
- каждый релиз имеет changelog, validation, rollback и документацию;
- номер версии не повышается задним числом и не придумывается вне фактического release unit;
- логотип считается утверждённым asset и не изменяется без прямой команды владельца.

Новые идеи во время активного release unit записываются в backlog и не расширяют
утверждённый scope. Перед началом новых продуктовых функций закрывается structural debt
предыдущего релиза либо владелец явно принимает документированный остаточный риск.

Порядок выкладки, гейты и откат — `docs/RELEASE_POLICY.md`.

## AI audit trail

Каждый реально выполненный значимый запрос сохраняется парой:

- `docs/ai_sessions/YYYY-MM-DD/NNN-...-prompt.md`
- `docs/ai_sessions/YYYY-MM-DD/NNN-...-response.md`

Ни одно значимое принятое решение не должно оставаться только в чате.

Адрес самого чата записывается в шапку файла ответа строкой `Chat: <url>` и
привязывается к карточкам доски трейлером `Board: chat <id> <url>`. У 147 карточек
первой сборки доски таких ссылок нет: восстановить адреса тех чатов неоткуда.

## Доска работ

Список работ по проекту — данные репозитория, а не память человека и не чат.
Карточки лежат в `docs/board/cards.json`, срез открытого — в `BACKLOG.md`,
живая доска — артефакт «Пульт Habitoff». Решение — `docs/decisions/ADR-0012-board-from-repo.md`,
порядок целиком — `docs/board/README.md`.

**Карточку двигает коммит, а не мышка.** Строка в сообщении коммита:

```
Board: done inf-users-migration
Board: doing inf-observability
Board: new bug P1 perf "Каталог запрашивается дважды" :: замер на старте, два дубля
Board: chat inf-observability https://claude.ai/...
```

Правила сессии:

- **закончил задачу — закрой её трейлером в том же коммите.** Не отдельным
  проходом «потом обновлю доску»: отдельный проход не случается, это и есть
  разрыв, из-за которого прод сутки отдавал чужое имя;
- **найденное попутно — `Board: new` в том же коммите, а не в текущую ветку.**
  Одна сессия — одна ветка — один критерий приёмки;
- **сессия привязывает свой чат** к затронутым карточкам: `Board: chat <id> <url>`.
  Иначе через месяц у решения не будет ни разбора, ни причины;
- в конце сессии: `node scripts/board.mjs apply && node scripts/board.mjs md`,
  отдельный коммит `board: применены трейлеры`;
- `node scripts/board.mjs check` входит в `scripts/state.sh` и в CI. Он падает,
  если трейлеры есть, а `cards.json` их не знает, и предупреждает, если коммит
  трогал `app/` или `supabase/` без единого трейлера.

Ручные правки на странице (перетащить, сменить приоритет, завести свою карточку,
написать заметку) остаются и пересборкой не стираются. Конфликт решается по дате
в одну сторону: правка побеждает, пока репозиторий не сказал новее.

## Git workflow

- работа ведётся в отдельной ветке от актуального `main`;
- foundation/code changes проходят validation;
- **сессия заканчивается пушем всего, что прошло проверку** — даже если PR ещё не готов
  и работа не закончена. Ветка, которая живёт только на одной машине, не существует ни
  для кого, включая её автора через три дня. За неделю до 27.08.2026 четыре сессии
  подряд оставили ветки локально по нескольку дней, и ни одна не нарушила правила,
  потому что этого правила не было;
- создаётся PR;
- принятой считается версия после merge в `main`;
- прод собирается только с `main`;
- **перед тем как что-то выкладывать и в конце сессии, которая трогала прод, — сверка:**

  ```bash
  node scripts/check-deploy-drift.mjs
  ```

  Она читает `https://habitoff.ru/version.json` и сравнивает коммит живой сборки с
  `origin/main`. Расхождение, продержавшееся больше суток, — сигнал, а не норма.
  Решение и причина — `docs/decisions/ADR-0009-deploy-drift-detection.md`;
- response/handoff обязан указать branch, PR, validation и незавершённые пункты.

## Decision gates

Обязательное согласование владельца до:

- смены privacy модели;
- destructive migration;
- смены домена, хостинга или identity provider;
- добавления внешнего сервиса в рантайм прода;
- введения коммерческой модели;
- изменения медицински значимых формулировок;
- изменения коэффициентов единиц;
- публикации пользовательского UGC без отдельного consent;
- замены утверждённой бренд-айдентики.
