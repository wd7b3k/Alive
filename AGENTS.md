# Правила работы AI с Habitoff

Корень репозитория `wd7b3k/Alive` — корень самостоятельного продукта Habitoff. Имя
репозитория историческое: до августа 2026 продукт назывался ALIVE.

**Этот файл содержит только то, что нельзя нарушать, и то, чем это проверяется.**
Почему каждое правило появилось — `docs/INCIDENTS.md`. Читать журнал перед задачей не
нужно; он существует, чтобы правило можно было объяснить, не удлиняя этот файл.

**Правило без проверки — не правило.** Новое правило добавляется сюда только вместе с
командой, которая падает при его нарушении. Пока команды нет, наблюдение живёт в
`docs/INCIDENTS.md` и не считается требованием к сессии.

## Пять инвариантов

1. **Репозиторий — единственный источник истины.** Решение, которого нет в git, не
   принято. Чат, память AI, локальный файл, ZIP, панель провайдера, SSH-сессия — не
   источник. При расхождении канон — репозиторий.
2. **Схема и содержимое базы меняются только миграциями из репозитория.** Прямой `psql`
   на боевой базе — чтение. Код edge-функций живёт в `supabase/functions/` и
   синхронизируется на сервер, а не правится там. Выкладка связана с конкретным коммитом
   и невозможна из грязного дерева.
3. **Privacy by default.** Данные минимизируются; чувствительный текст не уходит в общую
   аналитику; Смыслы и Связки не публикуются автоматически; UGC попадает в admin review
   только после явного «Предложить в общую базу»; группа «Вместе» работает на разрешённых
   агрегатах; секреты не попадают во frontend, git и логи.
4. **Никаких медицинских обещаний.** Продукт не лечит, не гарантирует отказ, не заменяет
   врача и не обещает продление жизни. Утверждение о здоровье имеет проверяемое основание
   и свежий авторитетный источник. Рабочие эвристики называются эвристиками
   (`1 кальян = 10 единиц`, `10 затяжек вейпа = 1 единица` — поведенческие эвристики,
   не эквивалент вреда).
5. **Не выполнено — значит не сделано.** Артефакт считается готовым только после того,
   как был выполнен, и проверка обязана уметь провалиться.

   | Что | Что значит «выполнено» |
   |---|---|
   | Функция в миграции | вызвана в `supabase/tests/local/`, тест зелёный |
   | Скрипт проверки | запущен на сервере, строка появилась в `ops.check_results` |
   | Скрипт эксплуатации | прогнан в режиме показа, вывод приложен |
   | Экран | открыт в браузере, состояние совпадает с ожидаемым |
   | Оповещение | отправлено тестовое сообщение и получено человеком |

   Имена (путь, метка, контейнер, переменная, код ответа) читаются из источника, а не
   придумываются. В отчёте владельцу «проверено» и «не проверено» разделены; отчёт без
   такого разделения недостоверен целиком.

## Правило → проверка

Правило из этой таблицы нарушить нельзя молча: команда падает. Значка ⚠ в таблице
больше нет: `T-20260906-03` закрыла все семь строк, у которых проверки не было.

Где проверка живёт, тоже важно. Джоб CI видит содержимое коммита и не видит рабочего
стола: файл, который не закоммичен, и `main`, который отстал, для него не существуют.
Такие правила проверяет `scripts/state.sh` на машине — первой командой сессии.

| Правило | Проверка |
|---|---|
| Ветка доведена до `origin`; работа не живёт на одной машине | `node scripts/check-local-drift.mjs` в `scripts/state.sh` |
| Постановка и документация — в git, а не untracked | `bash scripts/state.sh`, раздел «постановка вне git»: отделяет невыложенное от остатка удаления |
| Сессия работает от свежего `origin/main` | первая строка `scripts/state.sh`: «СТОП: локальный main отстаёт на N» |
| Прод собран с `main` и не отстаёт | гейт `HEAD == origin/main` в `infra/deploy/deploy.sh` — до сборки; `node scripts/check-deploy-drift.mjs` и `https://habitoff.ru/version.json` — постфактум |
| Число миграций равно числу записей в журнале | гейт в `infra/deploy/deploy.sh` |
| Секреты не уезжают в бандл | `node scripts/scan-bundle-for-secrets.mjs dist` в CI |
| Карточку двигает коммит, доска знает о трейлерах | `node scripts/board.mjs check` в CI |
| Каждая `admin_`-функция вызвана тестом, каждая проверка подключена к группе | `app/src/ops-contract.test.ts` |
| Изоляция арендаторов | `bash supabase/tests/local/run.sh` в CI |
| Формат, линт, типы, тесты, сборка | джоб `frontend-ci` |
| Номер ADR выдаёт скрипт, а не глаз | `scripts/next-adr.sh` |
| Номер постановки и записи сессии выдаёт скрипт | `scripts/next-id.sh`; коллизию ловит `node scripts/check-tasks.mjs` в джобе «постановка» |
| Тема задачи входит в список `epic` доски | `node scripts/check-tasks.mjs` в джобе «постановка» |
| Не больше двух `doing`, не больше трёх карточек с приоритетом 0, не больше одной неисполненной `T-` | `node scripts/check-limits.mjs` в джобе «пределы» |
| Число, которое проверяет машина, в документ не копируется | `node scripts/check-numbers.mjs` в джобе «постановка» |
| Карточка не уходит в `done` без ссылки на чат | `node scripts/board.mjs check`, предупреждение со счётом |
| Экран открыт в браузере, а не только отвечает кодом 200 | `node scripts/check-screen.mjs <адрес>`: видимый текст, `h1`, перелив |

## Порядок загрузки контекста

Читать весь `docs/` перед задачей не нужно и вредно. Порядок:

1. `docs/NAVIGATOR.md` — карта: что читать по теме, где состояние, какие расхождения известны;
2. вывод `bash scripts/state.sh`;
3. этот файл и `docs/CURRENT_STATE.md`;
4. два-три документа по теме — те, что названы в навигаторе;
5. действующие ADR по теме;
6. постановка `docs/tasks/T-….md` и разбор, из которого она выросла;
7. только затем — код.

Навигатор обновляется той же задачей, которая делает его неверным.

## Постановка

Порядок целиком — `docs/tasks/README.md`. Здесь только то, что нельзя нарушать:

- **разбор** `R-ГГГГММДД-NN-<тема>-slug.md` отвечает «надо ли и что именно» и
  заканчивается решением, подвешиванием или отказом;
- **задача** `T-ГГГГММДД-NN-<тема>-slug.md` заводится только после строки «Решение»;
- одна задача — одна ветка `task/<id карточки>` — одна карточка доски;
- номер берётся у `scripts/next-id.sh`, а не глазами;
- **раздел «Что расширяем» обязателен.** Названа существующая сущность, которую задача
  развивает, и сказано, почему её не хватает. Пусто — задача не принимается. Второй
  объект вместо расширения первого стоил проекту трёх переделок (`docs/INCIDENTS.md`);
- **раздел «Стоп-условие» обязателен.** Названо, что должно не сойтись, чтобы сессия
  остановилась и спросила. Допущение вместо вопроса разрешено только там, где стоп-условие
  его не покрывает;
- предпосылки проверяются первыми командами; не сошлось — стоп, а не починка по дороге;
- инварианты предлагает постановщик со ссылкой на источник; строка без источника
  помечается «предложено — подтвердить»;
- вопросов владельцу не больше трёх, и только те, ответ на которые меняет работу.

## Сеть агентов

Роли, границы и модели — `.claude/agents/`. Общие правила, одинаковые для всех:

- **одно рабочее дерево — один агент.** Переключать ветку в чужом дереве нельзя;
- **у каждого файла один владелец.** Список владения — в файле роли. Чужой файл не
  правится: изменение запрашивается у владельца или оформляется задачей;
- **роль подключается сама, по своему описанию.** Главный агент читает поле `description`
  и решает, кому отдать работу; руками роль звать не нужно. Описание — условие включения,
  а не подпись: в нём перечислены слова и события, при которых роль обязана вступить;
- **сказать «сделано» имеет право только приёмка, и она же доводит до прода.**
  Остальные отдают результат со словами «сделано и не проверено». Работа, не дошедшая до
  `main` и до живой сборки, не сделана;
- **роль не видит истории разговора.** В её контекст попадают собственный файл, задание,
  `CLAUDE.md` и предзагруженный скилл `habitoff-vhod`. Состояние, постановку и документы
  по теме она собирает сама — первым шагом, командами;
- **вход агента — его собственный файл роли.** Он не пересказывает этот документ:
  инварианты и таблица проверок действуют для всех и не дублируются в ролях;
- **модель выбрана по цене ошибки** и записана в роли. Агент не меняет её на ходу:
  если задача выше уровня роли, он останавливается и возвращает её с пометкой
  «нужна модель выше», а не догадывается;
- **найденное попутно — `Board: new` в том же коммите**, а не расширение текущей ветки.

## Git

- работа ведётся в отдельной ветке от актуального `main`, всегда после `git fetch`;
- **сессия заканчивается пушем всего, что прошло проверку**, даже если работа не закончена;
- **бандл в папке — не доставка**: ветка доставлена только после пуша в `origin`;
- **файл никогда не переписывается целиком по тексту, прочитанному раньше в сессии** —
  только точечная правка после свежего чтения;
- принятой считается версия после merge в `main`; прод собирается только с `main`;
- перед выкладкой и в конце сессии, трогавшей прод, — `node scripts/check-deploy-drift.mjs`;
- машина владельца — Windows: команды PowerShell 5.1, по одной на строку, без `&&`,
  файлы читать с `-Encoding UTF8`;
- `response`/`handoff` указывает ветку, PR, проверки и незакрытое.

## Пределы одновременной работы

- не больше двух активных задач (`doing`);
- не больше одной неисполненной постановки в очереди; эпик с принятым решением идёт по
  одной задаче — остальные помечены `Подвешена: ждёт закрытия предыдущей` и в очередь не
  входят;
- приоритет 0 означает «держит пилот» и выдаётся не более чем трём карточкам;
- общие файлы (`docs/decisions/*`, `docs/CURRENT_STATE.md`, `BACKLOG.md`, `cards.json`)
  правит только их владелец по `.claude/agents/`.

## Гейты решений владельца

Обязательное согласование до: смены privacy-модели; разрушительной миграции; смены
домена, хостинга или провайдера входа; добавления внешнего сервиса в рантайм прода;
введения коммерческой модели; изменения медицински значимых формулировок; изменения
коэффициентов единиц; публикации UGC без отдельного согласия; замены утверждённой
бренд-айдентики.

## Статус проекта

Habitoff — некоммерческий экспериментальный проект, возникший из личной потребности
автора. До отдельного решения владельца запрещено: оптимизировать продукт под выручку,
добавлять рекламу, строить рекламные профили, передавать чувствительные данные для
коммерческого таргетинга, делать монетизацию частью архитектуры. Изменение статуса
требует правки `docs/PROJECT_CHARTER.md` и отдельного ADR.

Решение о деньгах подвешено — `docs/tasks/R-20260830-01-money-monetization.md`.

## Авторство и заимствования

Habitoff — авторская система в смысле композиции и реализации, но не заявляет
исключительного происхождения всех идей. AI обязан отделять оригинальные продуктовые
решения от общеизвестных методик, не выдавать известные психологические, медицинские и
поведенческие техники за изобретение проекта, добавлять атрибуцию при опознанном
заимствовании и не копировать защищённые тексты без проверки допустимости.

## UX: ничего необъяснённого

Любая специфическая сущность, метрика или термин понятны человеку без знакомства с
проектом: понятное название, короткое объяснение на месте, «Подробнее» для глубины,
осмысленный пустой экран. Нельзя рассчитывать, что пользователь знает внутреннюю
терминологию.

## Архитектурная дисциплина

- не строить инфраструктуру «на будущее» без гейта; предпочитать простую модульную
  архитектуру; границы модулей и владение явные;
- приватные данные модуля не меняются из другого модуля в обход его публичного API;
- сырые поведенческие события хранятся отдельно от пересчитываемых моделей; изменение
  моделей единиц не переписывает историю;
- **никаких внешних сервисов в рантайме прода, кроме перечисленных явно.** Разрешены:
  Let's Encrypt, провайдеры входа при нажатии кнопки, счётчики Метрики и GA (ADR-0015).
  Служебный обмен между своими серверами (ADR-0013) под инвариант не подпадает. Всё
  остальное требует решения владельца.

## LLM

LLM помогает с объяснениями, классификацией UGC и разработкой, но не является источником
истины для статистики, не имеет привилегированного доступа к базе, не принимает решений
о безопасности и приватности, не назначает дозировку и не публикует UGC автоматически.

## Релизы

v2.7 — legacy и откат; v2.8 не является production release; каноническая линия начинается
с v3.0. У каждого релиза есть changelog, проверка, откат и документация. Номер версии не
повышается задним числом. Логотип — утверждённый ассет, меняется только по прямой команде
владельца. Новые идеи во время активного релиза уходят в бэклог и не расширяют его объём.
Порядок выкладки и откат — `docs/RELEASE_POLICY.md`.

## Запись сессий

Каждый значимый запрос сохраняется парой
`docs/ai_sessions/ГГГГ-ММ-ДД/NNN-…-prompt.md` и `…-response.md`; номер выдаёт
`scripts/next-id.sh`. Адрес чата пишется в шапку ответа строкой `Chat: <url>` и
привязывается к карточкам трейлером `Board: chat <id> <url>`.

## Доска работ

Список работ — данные репозитория: `docs/board/cards.json`, срез — `BACKLOG.md`, порядок —
`docs/board/README.md`, решение — ADR-0012. Карточку двигает коммит, а не мышка. Закончил
задачу — закрой трейлером в том же коммите. В конце сессии:
`node scripts/board.mjs apply && node scripts/board.mjs md`, отдельный коммит
`board: применены трейлеры`.
