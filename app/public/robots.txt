# Обход открыт весь, включая личные экраны. Запрет индексации личных экранов живёт не
# здесь, а в HTTP-заголовке `X-Robots-Tag: noindex, nofollow`, который отдаёт Caddy
# (`infra/caddy/Caddyfile`).
#
# Так сделано 05.09.2026, и это выглядит наоборот, но работает именно так.
#
# `Disallow` запрещает **обход**, а не показ. Робот, которому запрещено заходить на
# адрес, не увидит там никакого запрета индексации — и вправе оставить адрес в выдаче
# голой ссылкой, узнав о нём откуда-то ещё. А узнавать теперь есть откуда: владелец
# включил в Вебмастере обход по счётчикам Метрики, а счётчик по ADR-0015 стоит на всех
# страницах, включая личные. Метрика сообщит роботу про `/profile` и остальные.
#
# Мета-тег `noindex` эту дыру не закрывал: его ставит JavaScript, которого краулер не
# выполняет. То есть до этой правки настоящего запрета индексации личных экранов не
# существовало ни для одного робота — при том что документ утверждал обратное.
#
# Чтобы `noindex` сработал, страницу нужно **разрешить обходить** и вернуть запрет на
# ней самой. Обходить там нечего: без входа личные экраны отдают ту же оболочку
# приложения, что и любой другой адрес — проверено побайтно, все шесть отдают один и тот
# же документ. Личные записи лежат за политиками доступа в базе и в HTML не попадают
# никогда.
#
# Список путей сверяется с `src/services/seo.ts` и с `Caddyfile` тестом
# `services/robots.test.ts`: две копии одного списка руками расходятся, это уже
# случалось.
