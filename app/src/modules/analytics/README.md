# Модуль «Аналитика»

Отдельный модуль админки: продуктовые метрики, воронки, когорты, источники и отток.
Владелец модуля — тот, кто отвечает за продуктовые решения, а не за экраны участника.

## Граница

Наружу модуль отдаёт ровно три вещи — `index.ts`:

- `ANALYTICS_ROUTE` — адрес, по которому он подключён;
- `AnalyticsModule` — сам экран;
- `canSeeAnalytics(role)` — можно ли показывать ссылку.

Внутрь модуля никто не ходит: ни один файл вне `modules/analytics/` не должен
импортировать `port.ts` или отдельные части экрана.

Обратно модуль зависит только от `services/` и `env` — от общей инфраструктуры, не от
экранов участника. Из `RedesignApp` он получает роль и больше ничего.

## Адрес

`ANALYTICS_ROUTE` — единственное место, где записан адрес. Владелец уточнит его позже;
смена будет правкой одной строки, а не поиском по коду.

## Доступ

Роль `admin` из профиля прячет ссылку и экран. **Защищает не это.** Защищают функции в
базе: каждая из шести начинается с `private.is_alive_admin()` и отказывает всем
остальным. Спрятанная кнопка ничего не защищает — она только не мозолит глаза.

## Что модуль не делает

- **Не показывает идентификаторов участников.** Ни в одном разрезе. «Посмотреть, как идёт
  продукт» не должно превращаться в «выгрузить, кто когда курил». Отток даёт числа по
  сегментам; когда появятся пуши, спрашивать затихшего будет система, а не человек со списком.
- **Не показывает разрезов меньше трёх человек.** Тот же порог подавления, что у «Вместе».
- **Не рисует ноль вместо «нечем считать».** Ноль читается как «всё плохо», а не как
  «мы это не измеряем».
